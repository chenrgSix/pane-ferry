# macOS WindowHost（P1 开发预览）

真实 Swift/AppKit `NSWindow` 宿主，使用已配对设备的 QUIC 路由接收窗口画面和发送输入。窗口画面统一使用 H.264，启动参数 `--fps 30` 或 `--fps 60` 选择帧率上限，缺省为 60。运行中可从“显示 → 帧率”即时切换，断线重连保留当前选择；跨屏不会覆盖该选择。发布端能力和反馈自适应继续限制实际速率。窗口副标题显示实际收到的像素尺寸和近 2 秒接收帧率；超过 2 秒没有新帧时显示未收到新画面，不保留旧帧率。

## 构建与运行

macOS 12+，Xcode Command Line Tools / Swift 5.9+。先启动两端 窗渡 PaneFerry 并通过设备邀请配对。一般由启动器传入设备身份、网络状态目录和打包网络组件路径；不接受 SSH 登录参数。

```sh
cd apps/mac-windowhost
swift build -c release
.build/release/PaneFerryWindowHost \
  --native-peer DEVICE_UUID \
  --native-state "$HOME/.local/state/lan-remoteapp/network" \
  --native-helper /absolute/path/to/paneferry-network \
  --session SESSION_ID
```

新开应用时用 `--app APP_ID` 代替 `--session`。网络组件在本机桥接设备专属的私有 Unix socket；实际跨机数据使用 QUIC。断线恢复仍绑定原设备与原会话。

连接会在附着窗口之前协商 H.264；远端没有编码能力时明确报错。应用图标和图片剪贴板仍使用 PNG，它们不属于窗口视频流。

## 当前能力与限制

- 每个远端窗口一个 NSWindow；窗口标题、大小、焦点与父子窗口层级。本机红色关闭按钮和应用菜单的“断开并退出”都只断开控制，保留远端应用与会话；要结束应用，可在远端应用画面内退出。
- 源端确认会话结束（包括重连时发现会话已结束）后，关闭本地窗口并退出宿主，清理连接与重连定时器。只关闭某个源端子窗口不会结束其他窗口；画面暂时没有更新也不会作为退出依据。
- 源端主窗口最小化或隐藏时，本地保留窗口并显示“恢复源端窗口”按钮，暂停对旧画面的输入。点击后请求源端恢复，收到可见状态后继续操作；重连到已隐藏的窗口也能恢复。本机黄色按钮仍只最小化本机窗口，绿色按钮仍只控制本机全屏。
- 从启动器连接时，Dock 使用所选 Ubuntu 应用或运行窗口的图标；新建、接管和恢复会话复用已有图标缓存，不增加远端扫描。图标由本机匿名管道交付，仅接受大小受限的 PNG；断线重连保留图标。无有效图标时使用 PaneFerry 标识。
- Dock、应用切换器和本机应用菜单使用 Ubuntu 应用名称。启动器在本机私有 `WindowHosts` 目录缓存各应用的 `.app` 入口，包名与显示名称随应用匹配，按配对设备 UUID、应用和宿主版本隔离；更新不会改写运行中的宿主，也不修改正式安装包。断开重连后加载当前入口；网页或文档标题仍独立显示在窗口标题栏。
- H.264 通过系统 VideoToolbox 解码，优先启用硬件加速；解码后由 NSView/CoreGraphics 显示。未实现 Metal 或 WebRTC。依赖的 P 帧全部按顺序解码，只合并已解码的待显示图像；编码失败会中断视频连接，不会切回 PNG 窗口帧。
- 键鼠、滚轮与 Command→Control 快捷键。Command 快捷键成对发送按下/释放，重复由本机按键事件驱动，避免抬键事件缺失后远端持续输入字母。NSTextInputClient 在控制端保留预编辑，提交 Unicode 后交给 Agent；普通字母与输入法修饰键不再作为物理按键转给 Ubuntu 输入法。候选框以最近点击位置为锚，尚无精确远端插入点和周边文本协议，复杂输入法/替换范围与非 ANSI 快捷键仍待完整验收。
- 默认自动适应本机窗口，以内容区的逻辑宽高和远端已有缩放换算协议像素尺寸，不使用 Mac backing 像素密度，不发送切换 DPI 的请求；拖动中最多每 100ms 合并一次更新，松手发送最终尺寸。远端旧尺寸回包不会拉回本机窗口。自动和固定模式都按实际图像宽高比显示；重绘到达前保留上一帧的比例，超过渲染预算时保留窗口比例降低请求像素数。旧帧与新窗口尺寸不一致期间暂停新的鼠标点击，仍交付已按下按钮的释放。
- “显示”菜单可恢复自动适应窗口、适应可用屏幕、全屏或手动输入固定远端像素宽高；标题栏显示实际收到的分辨率。实际尺寸未匹配请求时等比留边，鼠标只在图像区域内换算，留边区域不向远端发送输入。标题区分实际接收像素、目标尺寸、等待重绘和预算限制，不把请求成功当成远端接受尺寸。
- 远端最大化、恢复或源端尺寸变化后，普通主窗口会重新同步本地目标尺寸；先等待 350ms，并最多补发两次，避免和应用的最小尺寸、字符网格约束反复争抢。短暂变化自行恢复时取消补发，弹窗、关联窗口及固定桌面/应用画布不参与。合成器换算造成的单像素取整视为匹配，标题仍显示实际接收尺寸。
- 界面缩放与分辨率分开：新独立会话、普通 Wayland 窗口和应用画布统一请求普通 1×，不按 Mac Retina 自动加倍；启动缩放设置已移除。Agent 的普通 Wayland 采集输出也遵循该请求，让应用原生绘制 1×。原桌面窗口显示“沿用应用缩放”，不把协议默认值当成实际 DPI。标题保留实际接收像素和本机逻辑点，不将本机 Retina backing 倍率额外标为画面放大。运行中仅调整窗口大小，不主动切换工具包 DPI；本机跨屏不改变远端 DPI；远端报告源缩放变化后按新倍率重新换算尺寸。手动输入可指定精确远端宽高。
- 父子关系有循环检查，但复杂菜单位置、模态阻塞、窗口跨屏和异常弹窗仍待实测。
- 编辑菜单或 Command+C/V 主动双向复制/粘贴文本、截图、PNG、普通文件及文件夹；Command+X 支持可编辑文本和图片的原生剪切。文件为复制，不做跨端移动。大内容使用独立的 QUIC 可靠流；回包关联、快速复制后粘贴的排队、缓存和大小限制见[剪贴板说明](../../docs/clipboard.md)。没有后台同步。
- 自动恢复原会话和窗口，也可从启动器手动恢复；宿主按应用生成独立 Dock 身份。文件拖放尚未实现。
- 输入队列、消息长度、编码包和画面尺寸、视频解码总像素、窗口数量及待显示图像像素有上限。H.264 SPS 尺寸必须匹配受限的元数据；原尺寸为奇数时仅补一行/列，解码后裁掉补边。resize、隐藏恢复和重连重建编码流并以关键帧开始；旧 geometry_revision、销毁窗口的旧图像会丢弃。已销毁 XID 在当前连接内复用会被拒绝，需重连重新获取快照。
- 不显示远端 stderr，不把按键/画面/剪贴板写入日志。桥接失败只显示退出码；在管理界面核查配对、地址和共享状态。

## 验证范围

已通过 Swift release 构建、Mac 原生 xterm 显示与输入，以及实际 QUIC 接收器的同会话自动恢复。待验收：Mousepad 与其他应用、复杂多窗口/模态菜单、跨屏、休眠唤醒、Intel Mac、性能与长期稳定性。完整记录见[验证记录](../../docs/validation.md)。
