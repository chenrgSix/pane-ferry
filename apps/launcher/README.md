# Tauri 启动器

Tauri 2 + Vue 3，通过固定 SSH 入口真实读取 Ubuntu 应用名称、图标及可接管窗口，显示可缓存的已安装应用、合并后的运行窗口和可选的自定义入口。使用打包的 Swift WindowHost 在 Mac 创建原生窗口。

## macOS 构建

需要已有 Rust、Node.js、Xcode Command Line Tools。运行 `cd apps/launcher && ./scripts/build-macos.sh`。脚本不安装系统软件。产物在 src-tauri/target/release/bundle/macos/，尚未签名公证；不要绕过系统安全警告。

浏览器单独 `npm run dev` 仅预览界面，不能执行 SSH。

## 连接与自动恢复

在启动器填写已验证的 Ubuntu 主机、账号和密码，点击“连接”。密码保存在 Mac 系统钥匙串，按主机、账号和端口隔离；localStorage 只保存连接偏好和应用目录缓存。更新密码时直接填写新值再连接，留空则使用已保存密码。不会创建 SSH 密钥或修改 Ubuntu 的公钥授权。

系统 SSH 通过打包 WindowHost 的 askpass 模式读取钥匙串，仅对密码提示提供当前端点的密码。秘密只经过匿名管道，不进入进程参数、环境变量、脚本或普通日志。帮助进程验证调用链必须来自本应用启动的 `/usr/bin/ssh`，直接 CLI 调用不能导出密码。首次主机指纹仍须通过可信渠道核验；不会自动信任未知或变化的主机身份。SSH 配置文件与转发保持禁用。

连接中断后自动按 1、2、4、8、15 秒退避重试，网络恢复事件会提前触发。原生窗口保留画面、大小和分辨率模式，重新认证后恢复原 session ID 与视频流；断线期间不接收或重放输入、剪贴板与关闭操作。主动退出立即停止重连。远端会话已结束时不另开应用；账号密码错误或主机身份变化时停止重试并提示更新配置。未收到首次启动响应时复用原 request ID，避免另开同一应用。

已安装应用缓存按端点保留，自动恢复仅更新窗口和会话状态；需要重新扫描安装目录时点击“刷新应用”。运行列表统一“连接”恢复已有会话或接管桌面窗口；不要求配置 apps.json。

原有系统密钥/agent 或临时登录通道仍可使用。维护辅助命令 `bash scripts/connect-ssh.sh HOST USER 22` 不保存密码，`--check` 只探测，`--disconnect` 关闭该临时通道；这不是日常自动重连的必需步骤。自动密码连接使用独立 `~/.ssh/lan-remoteapp-password-%C` 控制通道，不重置已有手工 SSH 连接。

## 结果与恢复

“客户端已启动”不等于“远端窗口已呈现”。连接错误由 WindowHost 显示。目录来自远端真实桌面入口及可选自定义配置，发现失败会明确提示。未确认的启动请求 ID 保存在本地，失败或重启启动器后再次点击同一主机和应用仍复用该 ID，避免网络重试重复启动。原生启动会先返回远端会话 ID，再附着 WindowHost。

运行列表把同一桌面窗口与已有会话合并为一行，点击“连接”附着既有会话；重连失败会提示并刷新，不自动另开应用。已连接的会话须先在原 WindowHost 中断开，再刷新。命令行 `--session` 仍可使用。文本、截图和文件复制/粘贴仅由主动操作触发，不做后台同步；文件拖放、打印、URL、音频和摄像头关闭。

已在 Apple Silicon Mac 与 Ubuntu 26.04 上完成 xterm 基础链路实测；完整验证范围见 `docs/validation.md`，其他应用仍须逐项验收。
