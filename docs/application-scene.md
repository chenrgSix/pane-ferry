# 应用会话画面（可选）

启动器“窗口显示 → 应用会话画面 · 试用”启用此模式。默认仍是原来的分窗口方式。首版支持 GNOME 50 中已打开的原生 Wayland 应用；不是 IDEA 专用判断。X11、其他发布平台和新启动的独立应用暂未接入此模式，明确返回不支持。

源端为选中的主窗口分配固定大小的虚拟输出，保留实际应用进程。主窗口最大化到该输出，使工具包根据真实可用区域定位、约束或滚动菜单。独立的 Clutter 场景只克隆主窗口及明确 transient 链的窗口 actor，沿用原坐标和堆叠顺序，背景不透明。每个会话只建立一个 PipeWire 采集流和 H.264 编码器；Mac 只建立一个会话窗口。没有在 Mac 上重新绘制菜单控件，也没有按应用名称、标题或 PID 扩张窗口范围。

场景建立以后才开始 RecordMonitor；可捕获的区域始终由上述不透明场景覆盖。新增 Shell 层会同步把场景置顶；锁屏或源端失效时画面变黑。释放时先停止采集并移除虚拟输出，再销毁遮罩；移除失败时保留遮罩。与同用户 GNOME 扩展一样，这属于组件范围校验，不是独立的操作系统沙箱。

键鼠仍使用现有 Portal/libei 授权。坐标按画布像素和输出倍率换算，检查当前命中对象与无关窗口重叠；不会向看不见的无关窗口发送点击。文本提交保留当前已授权的对话框焦点。窗口关闭、恢复、剪贴板沿用原接口。

画布在连接时按 Mac 可用区域和倍率确定，最多 4096×4096、总像素不超过 8M。之后拖动 Mac 窗口仅等比显示，不反复热插拔输出。重新连接保留原画布；显式重新启动接管请求可切换画布或显示方式，不结束原应用。超过 16 个同时显示的关联窗口会停止显示；不悄悄截断窗口集合。

编码和解码均从控制通道移到有界工作队列。此版本仍使用现有 GStreamer 编码及 VideoToolbox 解码后 CGImage 显示路径，不宣称全链路零复制或已实现 Metal 直显。

验证方式：

```sh
node tests/unit/application_scene.mjs
systemd-run --user --collect --wait --pipe python3 /absolute/repo/tests/e2e/wayland_smoke.py \
  --agent /absolute/paneferry-agent --application-scene-only --logical-wayland-scale 2
```

隔离 GNOME 的真实 H.264 像素测试覆盖 100%/200% 主窗口、对话框、嵌套菜单、短生命周期弹窗、同 PID 无关窗口、输入范围、输出释放后重连及切回分窗口模式。该结果不代替实际 IDEA 菜单滚动、Portal 输入和 Mac→Ubuntu 延迟测量。
