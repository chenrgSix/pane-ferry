# 同版本 ChatGPT 的无重启密度试验（2026-10-24）

**ChatGPT 可以在原进程中重新绘制 2× 像素，但本次验证的触发方式会影响共享 X 显示环境，尚无符合本任务边界的逐窗口修复。** 固定共享密度后，仅把目标移入高 DPI 输出会使字号和控件变小。没有修改或部署产品代码。

本轮从 `0e90121`、干净工作区开始，保留上轮诊断提交。结论修正了“X11 DPI 只能在启动时读取”的过宽表述；没有把“能够动态重绘”等同于“可以安全地只改接管窗口”。

## 同版本与隔离条件

- 安装包 `chatgpt 26.1013.40934`，随包运行时 `42.3.0`，GNOME Shell `50.1`、Xwayland `24.1.10`。
- 正式 ChatGPT PID 14785 的 `/proc/14785/exe` 与隔离试验使用的 `/usr/lib/chatgpt/ChatGPT` SHA-256 均为 `1391ebd71b4eda71684608c47a387aab54f0dcfe59832367fd9283bd8193ebf0`。原进程打开的 `app.asar` 与安装包文件设备号、inode 相同；包 SHA-256 为 `127889637eca45c38ab9dd0487043ad7d59c9c1c265551f1754e483ba24584a6`。
- 每组试验启动一次完整 ChatGPT，沿用该进程的 PID、start_ticks 和 XID 做 1×→2×→1× 对照；没有替换为 GTK 或自行编写的 Electron 页面。使用全新配置、离线登录界面，不读取或复制用户账号、聊天及原 profile。
- 最终脚本在 bubblewrap 的独立 PID、网络、IPC 命名空间运行，隐藏 `/home`、`/run` 和原 `/tmp`，根文件系统只读。私有 D-Bus 不激活宿主服务；GNOME、Xvfb、PipeWire、XSettings 和配置都属于试验。systemd 限制 4 GiB、200% CPU、512 tasks、240 秒，结束后回收整个试验单元和临时 profile。
- 无 GPU 设备的隔离环境使用 `--disable-gpu`。嵌套环境不能启动 Chromium 内层 sandbox，因此仅试验实例带 `--no-sandbox`，外层 bubblewrap 仍生效；正式程序启动参数不变。这个条件限制了结论，不能称为原桌面 GPU 和已登录内容的验收。

上游 Chromium 的 GTK 实现会在密度配置改变时通知显示观察者，X11 实现会更新显示列表；这提供试验线索，不是当前定制运行时的版本证明。实际能力以同二进制试验为准。[GTK 实现](https://github.com/chromium/chromium/blob/main/ui/gtk/gtk_ui.cc)、[X11 实现](https://github.com/chromium/chromium/blob/main/ui/ozone/platform/x11/x11_screen_ozone.cc)。

## 三组实测

基准均为 1200×800 逻辑区域。原图由现有 `quality_sample` 从目标的 X11 drawable / XComposite pixmap 获取；未对图片做放大后充当原图。另一个 GTK 窗口作为旁观者，记录其倍率、布局和文本。

| 试验 | 目标实际结果 | 旁观窗口及共享环境 | 是否可作为本次修复 |
| --- | --- | --- | --- |
| 私有 Xvfb，运行时 XSettings 1→2→1 | 原进程从 1200×800 重绘到 2400×1600；字号、按钮逻辑尺寸和位置保持，恢复后相同 | 旁观窗口倍率也从 1→2→1 | 否，通知作用于整个 X screen |
| 私有 GNOME，沿用现有 VirtualOutput 生命周期将 XWayland 目标移入 2× 输出 | 原进程、1200×800 逻辑区域保持，实际 2400×1600，字形确实重绘 | Xft.dpi 从 96→192；旁观窗口倍率 1→2，逻辑高度 450→432；原 XWayland 输出从 3000×2000 映射为 6000×4000 | 否，原显示环境和其他窗口也受到影响 |
| 同样的私有输出，但私有 XSettings 固定为 1× | 仍有 2400×1600 像素、合成器资源倍率仍为 2；字形却与 1× 原图逐像素相同，只改变位置 | 旁观窗口虽然倍率为 1，逻辑尺寸却从 700×450→1400×936；共享 XWayland 坐标范围仍改变 | 否，目标字号减半，且仍有旁观布局变化 |

第二、三组只在隔离扩展的**副本**中解除 X11 的 `ensureOutput` 跳过，并把输出就绪条件改为确认窗口已移入该输出，以观察真实结果；复用现有 `VirtualOutput` 的创建、移动与回收逻辑。没有重写虚拟输出，没有修改工作区/已安装扩展，也没有把请求的 scale=2 当作应用已经重绘的证据。这两处实验性放宽没有进入产品。

## 字号和布局的像素证据

测量离线登录页的实心按钮与标题字形边界，不依赖协议倍率。逻辑值按实际源宽高与 1200×800 的比例换算。

| 指标 | 1× 基准 | 确实动态重绘 2× | 共享密度固定 1×、仅扩大目标像素 |
| --- | --- | --- | --- |
| 原图 | 1200×800 | 2400×1600 | 2400×1600 |
| 按钮像素尺寸 | 340×48 | 680×96 | 340×48 |
| 按钮逻辑尺寸 | 340×48 | 340×48 | **170×24** |
| 标题字形像素边界 | 239×26 | 478×52 | 239×26 |
| 标题逻辑边界 | 239×26 | 239×26 | **119.5×13** |
| 按钮逻辑左上角 | (430,371) | (430,371) | (515,385.5) |

动态 2× 的字形与将 1× 字形双三次插值到相同大小的结果不同，RGB MAE 为 14.366（0–255）；固定密度组字形与原 1× 字形的差值为 **0**。这不是可读性评分，而是结合实际客户区、字形大小和来源捕获，排除“只是截图变大”的证据。

原始图片只含全新离线实例的登录界面：[1× 基准](validation-artifacts/2026-10-24-chatgpt-isolated-1x.png)、[显示级动态 2×](validation-artifacts/2026-10-24-chatgpt-isolated-2x.png)、[固定共享密度的反例](validation-artifacts/2026-10-24-chatgpt-isolated-fixed.png)。不要把这些图片当作原已登录窗口的实测。

## 恢复与状态边界

实验性 X11 私有输出释放后，还观察到一个过渡错配：合成器已报 1280×820、scale=1，X11 客户区仍为 2560×1640。脚本把这个阶段记为 `after-release`，不称为恢复成功；随后重新建立 1× 试验输出并显式配置 1200×800，才记录目标尺寸及字形恢复。普通 GNOME 组的最后一次旁观窗口采样为 350×235，未证明恢复到初始 700×450。

这些结果进一步说明，不能只删除 X11 跳过条件就交付修复。它们来自实验性 X11 输出路径，不是当前用户 ChatGPT 接管路径已出现该问题的证明。本轮没有修改共享的恢复或几何逻辑。

## 复现和本轮验证

先在 Ubuntu 的私有仓库副本构建现有采样 example；脚本要求准确的已核实程序哈希，拒绝覆盖结果目录。以下三种 mode 各用一个新目录运行：

```sh
cargo build --locked -p paneferry-agent --example quality_sample
python3 tests/e2e/chatgpt_density_probe.py x11 \
  --probe target/debug/examples/quality_sample --output /tmp/新的结果目录 \
  --expected-sha256 1391ebd71b4eda71684608c47a387aab54f0dcfe59832367fd9283bd8193ebf0
# 将 x11 分别换成 gnome、gnome-fixed，使用另外两个新目录。
python3 tests/performance/chatgpt_density_metrics.py /tmp/对应的结果目录
```

脚本以 PID/XRes 身份确认目标；窗口标题不参与选择。缺少依赖或请求尺寸未达到时会失败；不会用请求值替代实际捕获值。输出包含原图、同帧编码数据、状态记录和日志；临时 profile 自动删除。

Mac 可继续复用上轮的离线解码和绘制工具：

```sh
python3 tests/performance/quality_sample_mac.py /本地结果目录/density-2x \
  --content-points 1200 800 --backing 2
```

本轮已对基准、真实 2× 重绘、固定共享密度三个样本各解码 6 包 H.264，输出尺寸全部保持。复用未修改的 SurfaceView 离屏绘制时，imageRect 为 1200×800 points、2400×1600 backing pixels；三者像素放大比分别为 2、1、1。后两者的字号仍有一倍差异，因此 1:1 像素显示本身也不能证明逻辑字号正确。

本轮修改前后完整 `scripts/check.sh` 均通过（Rust 59 passed / 6 ignored、前端 32 passed，以及 Swift/AppKit、连续 resize、旧帧、输入释放、关闭/重连、隔离 QUIC/H.264）。三个整理后的 Ubuntu 试验、原图测量、正常启动 `hidpi_smoke.py` 和诊断参数拒绝检查的最终结果见[结构化记录](validation-artifacts/2026-10-24-chatgpt-isolated.json)。

没有生产端画质改善、已登录 ChatGPT 内容/输入、菜单/transient、真实 GNOME 关闭竞态、多屏、GPU 或持续带宽/CPU/帧率/延迟验收。实验运行资源上限不能当作生产性能测量。正常启动路径的流程、默认参数、DPI 和编码均未更改。

## 决定

目前的障碍是**重绘触发的作用范围和共享 XWayland 坐标变化**，不是同版本程序完全没有动态高清绘制能力。本轮已证实的两个机制都不能满足只影响接管窗口的边界，因此只提交可复现试验与证据，没有采用扩大 DPI、自动 zoom、进程注入或调高码率的产品改动。

这不是对所有 X11 应用或未来合成器能力的普遍否定。若继续研究，必须先找到该运行时与合成器可用的逐窗口密度通知，并证明旁观窗口、字号、布局和输入都保持；仅看到 scale=2 或 2400×1600 不足以进入实现阶段。

结束时正式 ChatGPT、GNOME、Agent 和网络进程启动计数均保持，正式服务 active，已安装 Agent/扩展哈希不变；临时试验单元及远端临时目录已清理，SSH 主连接已关闭。没有部署、push、PR 或 VPN 变更。

撤销本轮只需先 revert 本报告的证据提交，再 `git revert 1c67f30` 撤销两个新增试验工具；具体证据提交 SHA 见交付消息。上轮 `407515a`、`0e90121` 的诊断成果不属于本轮撤销范围。
