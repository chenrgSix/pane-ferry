# 窗渡 PaneFerry 使用教程

适用于 **v0.1.1 开发者预览版**。两端各安装一份窗渡，就能在 Mac 使用 Ubuntu 应用，也能在 Ubuntu 使用 Mac 应用。应用继续在原设备运行，文件保存在原设备；复制文件需主动使用剪贴板。

## 1. 下载与安装

从 [v0.1.1 发布页](https://github.com/chenrgSix/pane-ferry/releases/tag/v0.1.1) 下载对应安装包和 `SHA256SUMS`：

| 设备 | 安装包 | 支持范围 |
| --- | --- | --- |
| Apple Silicon Mac | `paneferry-v0.1.1-macos-arm64.zip` | 要求 macOS 13 或更高；本次构建与门禁在 macOS 27.0.1 完成 |
| Ubuntu x86_64（推荐） | `paneferry_0.1.1-1_amd64.deb` | 本次在 Ubuntu 26.04.1 / GNOME 50 构建；其他发行版、旧版 glibc 与桌面环境未验收 |

Mac 用 `shasum -a 256 安装包文件名`，Ubuntu 用 `sha256sum 安装包文件名`，将输出与 `SHA256SUMS` 中对应文件的值核对。不要将源码 ZIP 当作可直接运行的安装包。

### Mac

1. 解压 ZIP，将 **窗渡 PaneFerry.app** 拖入“应用程序”，打开它。
2. 本预览包使用临时签名，尚无 Apple Developer ID 签名和公证。若 macOS 拦截，确认来源与校验值后，按“系统设置 → 隐私与安全性”的提示允许打开。
3. 仅接收 Ubuntu 应用不需要 Mac 的录屏和辅助功能权限。需要将 Mac 应用提供给 Ubuntu 时，再完成第 5 节的本机共享授权。

升级时先断开接收窗口并退出旧版本，再替换应用。原有设备身份和配对保留；临时签名可能导致共享组件权限需要重新授予。

### Ubuntu：双击安装（推荐）

1. 下载 `paneferry_0.1.1-1_amd64.deb`，在“文件”中双击它。
2. 使用“应用中心 / 软件安装”打开，点击“安装”，按系统提示输入本机管理员密码。包管理器会下载所需依赖，因此首次安装需要可用的软件源和网络。
3. 安装完成后，在应用菜单搜索并打开 **窗渡 PaneFerry**。后台组件以当前登录用户身份启动，无需手动运行安装脚本或以 root 身份打开程序。
4. 要接管原桌面 Wayland 窗口，在“扩展”中启用“窗渡 PaneFerry”。首次安装可能需要保存工作后注销、重新登录，让 GNOME 识别扩展；独立 X11 应用不需要这一步。

如果双击没有进入安装器，右键选择“打开方式 → 应用中心 / 软件安装”，也可使用 GDebi。测试中的隔离 Ubuntu 26.04 桌面使用 GDebi 完成了文件管理器双击安装；这不代表所有应用中心版本都已实测。可选命令行安装方式是：

```sh
sudo apt install ./paneferry_0.1.1-1_amd64.deb
```

`.deb` 安装到系统目录，程序入口为 `/usr/bin/paneferry`，许可证在 `/usr/share/doc/paneferry/LICENSE`。安装、重装和升级不会主动停止正在运行的 Agent 或应用；保存工作并退出旧会话后，再重启用户服务或重新登录使用更新。卸载前也应保存并关闭应用，随后从软件管理器移除，或运行 `sudo apt remove paneferry`。卸载不会删除用户的配对、配置和数据。

**从旧脚本版切换：** 旧版的用户级桌面入口和服务配置会优先于系统包，不建议直接混用。先保存独立应用中的工作，断开接收窗口并关闭旧管理界面；备份并移走 `~/.local/share/applications/io.lanremoteapp.launcher.desktop` 和 `~/.config/systemd/user/remoteapp-agent.service`，停止旧 Agent 后执行 `systemctl --user daemon-reload`，再打开 `/usr/bin/paneferry`。已有设备身份仍保留。旧用户目录的 GNOME 扩展也会优先于系统扩展，切换扩展版本需备份旧扩展目录并在保存工作后重新登录。普通脚本版升级仍可沿用下面的 tar 包方式。

### Ubuntu：脚本安装包（保留兼容）

`paneferry-v0.1.1-linux-x86_64.tar.gz` 仍可下载。此方式安装到当前用户目录；请与 `.deb` 选择一种使用。先登录 Ubuntu 图形桌面，在终端安装运行依赖：

```sh
sudo apt update
sudo apt install python3-gi python3-gi-cairo python3-websocket \
  gir1.2-gtk-3.0 gir1.2-gstreamer-1.0 gir1.2-gst-plugins-base-1.0 \
  gstreamer1.0-plugins-base gstreamer1.0-plugins-good \
  gstreamer1.0-plugins-bad gstreamer1.0-libav gstreamer1.0-pipewire \
  xvfb openbox xauth dbus-x11 xdg-dbus-proxy libei1 libx11-6 \
  xdg-desktop-portal xdg-desktop-portal-gnome
```

在下载目录解压并安装：

```sh
tar -xzf paneferry-v0.1.1-linux-x86_64.tar.gz
cd paneferry-v0.1.1-linux-x86_64
bash install.sh
```

安装脚本以当前用户运行，**不要加 sudo**。安装后从应用菜单打开“窗渡 PaneFerry”，或运行：

```sh
~/.local/bin/paneferry
```

安装包包含 Agent、网络组件、GTK 管理/接收界面和 GNOME 扩展。GNOME 50 首次安装扩展后可能要保存工作并注销、重新登录，才能接管原桌面上的 Wayland 窗口；安装脚本不会自动注销。可在扩展管理器确认“窗渡 PaneFerry”已启用。独立 X11 应用不依赖该扩展。

已有 Agent 运行时，普通安装会在写入前停止并给出提示。升级改用：

```sh
bash install.sh --defer-restart
```

这一步更新文件，保留正在运行的 Agent 和应用。**先保存 Agent 启动的独立应用中的工作，并断开接收窗口、关闭管理界面**，再执行：

```sh
systemctl --user restart remoteapp-agent.service
~/.local/bin/paneferry
```

Agent 重启会结束其独立会话中的应用，之后需要重新打开，旧会话 ID 和未保存状态不能恢复。接管的原桌面应用不由 Agent 结束。首次安装与升级的详细行为见 [Linux Agent 指南](linux-agent.md)。

## 2. 配对两台设备

1. 两台设备连接同一个可互通的局域网，并分别打开窗渡。网络组件默认使用 **UDP 42424**；产品不自动修改防火墙、不提供公网穿透。
2. 在 Mac 的“设备管理”点击“生成本机邀请”；也可以从 Ubuntu 点击“生成配对邀请”。
3. 在另一端填写生成邀请那台设备的地址，例如 `192.168.1.20:42424`，粘贴邀请并点击“配对设备”（Ubuntu 为“配对”）。地址用实际局域网 IP，不能填 `127.0.0.1`。
4. 邀请有效期为五分钟且只能使用一次。配对成功后，两端都保存对方身份，一次配对即可双向使用。之后通常无需再输入邀请。

配对不需要 SSH 账号或密码。通过可信方式传递邀请，不要放进公开截图、Issue 或仓库。设备 IP 改变时在“设备管理”更新地址；不要复制其他设备的身份文件。

## 3. 在 Mac 使用 Ubuntu 应用

先在 Ubuntu 管理界面确认本机共享已开启，再在 Mac 的“应用工作台 → 应用来源”选择这台 Ubuntu。

| 想做什么 | 操作 | 会发生什么 |
| --- | --- | --- |
| 启动一个应用 | “已安装应用”中点击“打开应用” | Ubuntu 在独立虚拟桌面启动实例，Mac 出现接收窗口 |
| 接管已经登录、正在使用的应用 | “运行中的窗口”中选择标为“原设备窗口”的目标，点击“连接” | 使用原进程、原登录状态；输入和窗口操作作用于这个真实窗口 |
| 返回已断开的独立应用 | “运行中的窗口”中找到标为“远程应用”的条目，点击“连接” | 继续原会话，前提是 Agent 和应用仍在运行 |
| 应用安装或卸载后更新列表 | 点击“刷新应用” | 重新读取对方设备的应用目录 |

新实例与原桌面实例可能有不同的登录状态；某些单实例应用会把启动交给已有进程，此时从“运行中的窗口”连接。看到“启动中的应用”时可等待自动更新或点击“检查状态”，无需重复启动。

首次接管 Ubuntu 原桌面窗口时，请在 **Ubuntu 本机** 的“窗渡 PaneFerry Agent”系统控制授权弹窗点击允许，并按需保留“记住”选项。这个系统弹窗不会出现在 Mac 的目标应用画面内。未授权时可能有画面但不能操作；授权取消后可主动重新连接。独立虚拟桌面应用不需要原桌面输入授权。

### 大小、输入与剪贴板

- Mac 接收窗口的“显示 → 自动适应窗口”跟随本机窗口尺寸；“设置分辨率…”可指定固定渲染像素。窗口副标题显示实际收到的尺寸和视频模式。
- “显示设置”里的新会话缩放只影响之后启动的独立应用；是否采用取决于应用工具包。它不会更改已运行应用的全局 DPI。
- 中文在控制端输入法中组合后提交。复制和粘贴用接收窗口“编辑”菜单或快捷键；只在主动操作时传输，不持续同步两端剪贴板。不同方向和窗口类型支持的格式与上限见[剪贴板说明](clipboard.md)。
- 源窗口被最小化或隐藏时，点击画面中的“恢复源端窗口”。复杂系统弹窗、外部查看器与应用自己的关联窗口兼容性并不相同。

### 断开与退出

关闭 Mac 接收窗口，或选择“断开并退出（保留远端应用）”，只断开控制，远端应用继续运行。需要退出远端程序时，使用其**画面内**的关闭按钮或应用退出菜单。独立会话的最后一个应用窗口关闭后，该会话会清理。

短暂网络中断时窗口会自动尝试重连；恢复时不补发断线期间的键盘、鼠标和剪贴板操作。远端应用已退出、Agent 已重启或配对已撤销时，不能靠重连恢复原会话。

## 4. 接管 ChatGPT 时自动 2× 高清

此功能适配 Ubuntu 上可执行路径为 `/usr/lib/chatgpt/ChatGPT` 的 XWayland 应用，已验证应用版本 **26.1013.40934**、源端密度 1×、Ubuntu 26.04 / GNOME 50。其他版本、浏览器网页或其他 Electron 应用不保证支持。

首次使用需要在 Ubuntu 为现有 ChatGPT 准备本机控制入口。**先保存 ChatGPT 中的工作，该步骤可能重启整个 ChatGPT 应用。** 在终端用 `pgrep -af 'chatgpt|ChatGPT'` 查看进程，核对主进程 PID（不要选择带 `--type=renderer` 等参数的子进程），将下面的 `12345` 替换为实际值：

```sh
/usr/bin/paneferry-agent prepare-chatgpt 12345
```

上述命令以 `.deb` 安装为例；脚本版将 `/usr/bin/paneferry-agent` 换成 `~/.local/bin/paneferry-agent`。命令核验当前用户、准确可执行路径和启动参数，已准备的进程会直接返回；不支持的启动方式会拒绝处理。准备时沿用原 profile；添加的回环调试入口具有应用控制能力，应仅在可信本机使用。关闭 ChatGPT 后用普通方式重新启动，可能需要再次准备。

准备完成后，在 Mac 的“运行中的窗口”连接目标 ChatGPT：

1. 自动开启 **2× 页面高清**，并将目标窗口移到同一 Ubuntu 桌面会话中的私有虚拟显示器。无需每次手动开启；重连也自动开启。
2. 在“显示 → ChatGPT 页面高清（2×）”可关闭本次连接的高清；1× 不迁移到虚拟显示器。
3. 关闭高清、主动断开或连接异常丢失时，会恢复目标窗口的页面设置、原位置和大小，并释放虚拟显示器。虚拟显示器创建失败时不启用高清。

页面适配仅选中目标窗口；同进程其他主窗口的缩放不随之改变。虚拟显示器仍属于同一桌面，宿主机概览可能看到目标，键鼠焦点仍共享。显示器热插拔实测曾让无关应用短暂调整高度后恢复，因此不能承诺整个宿主桌面完全无感。系统原生菜单、文件对话框不属于页面高清；桌面崩溃或恢复辅助进程被强杀等情形，也不保证自动恢复。实测证据与边界见 [ChatGPT 页面高清](chatgpt-page-scale.md)。

## 5. 在 Ubuntu 使用 Mac 应用

1. Mac 打开“本机共享”，点击“开启共享”。
2. 点击“允许共享所需权限”，按系统提示给予共享组件录屏和辅助功能权限。仅给管理界面权限不能替代组件权限。
3. 若权限列表已打开但检测仍失败，点击“显示共享组件”，给访达选中的 **PaneFerryNode.app** 授权；临时签名升级后可能需要移除旧条目再添加当前组件。
4. Ubuntu 选择已配对的 Mac，读取应用目录并打开应用，或连接已有窗口。

Mac 应用继续显示在 Mac 当前登录桌面，不创建独立 Mac 后台桌面。关闭 Ubuntu 主接收窗口只断开；关闭关联预览仅关闭对应预览。停止 Mac 本机共享会释放发布控制，保留应用，也不结束 Mac 正在接收的 Ubuntu 应用。详见 [Mac 发布指南](mac-publishing.md)。

## 6. 整桌面模式（实验功能）

Mac 工作台的“整桌面”列出 Ubuntu 当前登录桌面的可用显示器。点击“连接桌面”会看到该显示器的整个画面，并使用 Ubuntu 的系统输入授权。调整 Mac 接收窗口只改变本机显示方式，不修改远端显示器分辨率；关闭接收窗口保留原桌面和应用。

目前只支持 Ubuntu GNOME/Wayland 桌面发布，不支持 Mac 整桌面发布、登录界面或无人登录后的唤醒。此模式尚未完成完整双机桌面控制验收；测试范围与尺寸限制见[整桌面模式说明](desktop-mode.md)。

## 7. 常见问题

| 现象 | 排查方法 |
| --- | --- |
| 配对失败 | 检查两端管理界面、局域网 IP、UDP 42424 可达性和邀请时效；重启或生成新邀请会使旧邀请失效 |
| 没有应用或窗口 | 确认对方本机共享开启，点击“刷新应用”或“刷新运行状态”；原生 Wayland 窗口还需 GNOME 50 扩展 |
| 有画面但鼠标键盘无效 | 查看源设备的系统授权弹窗和接收窗口状态；Mac 发布需共享组件录屏与辅助功能权限 |
| ChatGPT 未开启高清 | 核对应用版本、1× 源密度、准备命令和 GNOME 虚拟显示器支持；未知布局会明确拒绝，按提示处理 |
| 远端应用重启后旧条目不能连接 | 刷新运行状态，选择新窗口；已退出的会话不能恢复 |
| 升级提示服务正在运行 | 使用 `--defer-restart`，保存独立应用工作后再手动重启 Agent |

Ubuntu 可用以下命令查看服务与依赖状态（脚本版将 `/usr/bin/paneferry-agent` 换成 `~/.local/bin/paneferry-agent`）：

```sh
/usr/bin/paneferry-agent check
systemctl --user status remoteapp-agent.service
journalctl --user -u remoteapp-agent.service -n 60 --no-pager
```

提交问题时提供两端系统版本、安装包版本、操作步骤和错误信息。分享日志前去掉邀请、身份私钥、个人内容和其他凭据。
