# X11 读回优化：同轮对照、60 帧补测和部署

2026-10-27，基线 `14323d9`，新版 Agent `c0d6d74`。
**这轮没有达到端到端延迟减半。** 同条件 1×、30 FPS 的 X11 中位数从 **85.407 降至 73.613 ms**，
减少 11.793 ms（13.8%）；P95 从 **134.879 降至 102.756 ms**，减少 23.8%。
另做新版 30/60 FPS 对照，X11 中位数为 **77.343 / 58.290 ms**；这是帧率实验，不能全部记成代码优化收益。

[脱敏原始时间线](2026-10-27-x11-readback.raw.jsonl.gz)包含正式、诊断、未采用试验和失败记录。
原始包不含视频像素、配对身份、剪贴板或用户应用内容；session ID 使用一致别名。

## 条件与测量边界

- Mac 到 `10.0.1.66`，路由仍为 `utun4`，本次小包 RTT 约 19 ms。不能与历史物理局域网
  `192.168.1.254` 的 69.4 ms，或上一轮不同时间的 93.6 ms，直接相减当作本次收益。
- 自有 GTK 输入计数夹具，每 33 ms 更新一小块动画；输出 1470×809、1×，Mac 显示区 1445×793 点、60 Hz。
  X11 源本身保留 2940×1618、2× backing；原生 Wayland 源为 1470×809、1×。
  分辨率、H.264 编码质量、GOP 与硬件解码保持一致。
- X11 8 轮顺序：旧、新、新、旧、新、旧、旧、新；每轮按键、点击各预热 2 次，各正式采样 30 次。
  原生 Wayland 另测旧、新、新、旧，各版 120 条有效响应。
  正式比较使用未插桩 Agent 和原网络程序，不并行编译或运行门禁；不丢弃尖峰。
- 每条响应核对输入序号、源端绘制计数与尺寸、最终帧 ID、输出缩放、协商帧率和硬件解码。
  30/60 是协商输出上限，不表示静态或每 33 ms 小块动画夹具持续产生 60 张不同画面。
- 起点是 Mac SurfaceView 输入函数；终点是 AVFoundation renderer 返回对应 IOSurface 的显示缓冲可用时刻。
  不包括外设、屏幕扫描、面板响应，也不是高速摄影的 input-to-photon。
  两端各用自己的单调时钟做差；混合残差不是跨机器直接相减得到的单向网络时间。

## 代码改动

1. `741c2bb`：X11 窗口结构、标题、尺寸、状态及子窗口变化通过事件唤醒维护。
   像素 damage 只唤醒采集；普通输入后不再以每 16.7 ms 为周期做完整窗口扫描。
   保留 100 ms 周期兜底，窗口消失的竞态不会永久关闭事件发现。
2. `c0d6d74`：在选定窗口的 XRender drawable 上做双线性缩小，再通过 MIT-SHM 读回输出尺寸的快照。
   2×→1× 时读回数据量约减少 75%，避免把整张 2× 像素先读进 CPU 后再缩小。
   将有序 Render 请求一并提交后检查，减少逐条命令的同步往返。
   只操作已授权 drawable 和私有目标 pixmap；保留不可变像素快照，不能把仍会被服务端改写的 SHM 直接借给编码器。
3. 缩放前校验 named pixmap 的实际尺寸和深度；过期尺寸不能被静默拉伸。
   不支持 RENDER、格式不兼容或缩放失败时走已有读回/转换回退；源应用的缩放、内容和进程保持不变。

没有应用名分支，也没有降低分辨率、QP 或编码质量来获取上述正式对照收益。

## 诊断与未采用的方案

- 原始 X11 诊断中，capture P50/P95 为约 12.27/19.95 ms，之后缩放、转换和编码约 8.72/10.93 ms；
  完整元数据扫描约 6.33/10.00 ms。这是优先处理 X11 的直接线索。
- 后续两端完整插桩的对照共 160 条，整体 P50 为 174.08→159.67 ms，明显高于未插桩正式测量，
  不混入正式统计，也不把它当作生产绝对延迟。它显示输入分发和读回存在等待，转换/编码部分缩短；
  观测扰动与运行条件的贡献尚未唯一分离。
- 这批传输诊断中的 QUIC RTT 约 19.2–23.5 ms，观测到的 lost packets 为 0；
  大关键帧可分多个发送批次，Quinn pacing 是线索，并不足以支持关闭拥塞控制。
  不能用这批“无丢包”记录断言未插桩正式尖峰也没有丢包。
- 另对 BBR 与现有 CUBIC 做同条件交替实验，各路径各版本 80 条：
  原生中位数 76.375→77.990 ms，X11 78.587→83.526 ms，没有稳定收益。
  **BBR 未提交到正式传输代码，也未部署，正式网络仍保持原配置。**
- 新版单独 30/60 FPS 试验，X11 各 80 条：P50 77.343→58.290 ms，
  P95 260.219→89.939 ms，但最大值分别仍为 442.456/485.543 ms。
  尾部受少量尖峰影响，样本量也小于正式代码对照；这不是稳定尾延迟已经降到 90 ms 的保证。
  用户的帧率设置未被自动改为 60。
- 额外原生 FPS 试验两次中止：源夹具分别停在计数 4 和 2，下一次按键的响应未到达。
  原生正式 30 帧对照此前全部通过。停止额外 Agent 后，正式安装的单实例 30/60 帧各 20 条键鼠响应通过。
  这些事实不能唯一证明多实例是原因。两次失败保留；首次失败的完整源日志已被重试覆盖，
  Mac 预热、待处理输入和读取时的源计数观测仍可核对，不用成功重试抹掉失败。
