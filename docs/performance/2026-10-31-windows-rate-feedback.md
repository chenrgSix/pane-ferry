# Windows 画质约束阻碍码率反馈

用户复测 d45dd2d：4:4:4 不再闪烁，但卡顿重新出现。本轮继续从 Windows 侧排查，
没有要求用户先调查 Mac，也没有回退按需关键帧或 BBR 对照设置。

## 现场证据

发布进程 17712 的 4096×1740 载体、60 fps 会话中：

- 编码常见 6–9 ms，Mac 稳定阶段解码常见约 3 ms。
- 反馈的传输与桥接剩余耗时 P99 达到约 150–283 ms；它包含 IPC/解析，
  不能当作纯网络 RTT。QUIC RTT 约 21–34 ms。
- 目标码率比例依次降至 800、640、512、409、327，但连接总发送量仍高。
  部分 2 秒采样中约 73–88 Mbps，QUIC 判定丢失 2364–5980 个包，
  最严重采样约 7.88 MB 丢失。发送量包含重传及该连接上的其他流，
  不能据此直接推算原始视频编码码率或链路容量。

## 隔离和修正

新增 `bitrate_adaptation_probe`，使用 2560×1440 合成画面：大部分为静态灰度
网格，底部 1/16 高度是逐帧变化的 32×32 色块。4:4:4 载体 4096×1800。
先编码 180 帧，再将目标码率设为 25%，再编码 180 帧；各阶段预热 60 帧，
按后续 120 帧的编码字节数和 60 fps 时间基准计算码率，不使用测试的墙钟速度。

| 配置 | 高目标阶段实际码率 | 低目标阶段实际码率 | 低阶段目标 |
| --- | ---: | ---: | ---: |
| 硬件，固定最大 QP 28 | 72.34 Mbps | 40.97 Mbps | 18.43 Mbps |
| 硬件，恢复编码器自适应量化范围 | 72.76 Mbps | 17.52 Mbps | 18.43 Mbps |
| 软件，恢复编码器自适应量化范围 | 29.71 Mbps | 16.13 Mbps | 18.43 Mbps |

旧配置在同一回归中超过低目标预算而失败；新版硬件和软件均通过，且全程只在
启动产生一个 IDR。固定 QP 下限使实际输出无法进一步下降，是本轮确认的
Windows 问题。更极端的随机画面即使恢复量化范围也可能超过目标预算，
所以这里不将 CBR 或此修正描述为任意内容下的硬字节上限。

删除固定最大 QP 28，保留 CBR、短 HRD、无 B 帧和按需 IDR，让既有反馈控制
能真正降低输出码率。弱网下画质仍可能下降，这是有损编码的取舍；不降低
源画面尺寸、帧率上限，也不把 4:4:4 改成 4:2:0。

新增由 `PANEFERRY_VIDEO_TIMING=1` 启用的 `PF_ENCODER_OUTPUT`：每约 2 秒
记录编码字节数、帧数、关键帧数、最大帧及当前目标码率，避免再把 QUIC 总发送
量误当作视频输出量。仅记录数值，不保存实际应用画面。静止/暂停后的统计窗口
可能包含空闲时间；目标值是打印时的当前值，不能将跨调整窗口当作固定目标采样。

## 闪烁回归

使用同一个 WinForms 滚动夹具，本机采集新版 600 帧并独立解码：只有启动 IDR，
平均 38.62 Mbps、帧大小 P99 139,668 B、最大 320,982 B。
原先出现色块的第 59/60/61 和 299/300/301 帧，灰度区采样色度平均误差
小于 0.001，没有重新出现周期偏色。没有将这项合成测试等同于用户真实视频验收。

本机交付间隔 P99 27.93 ms，另有一次约 81 ms 间隔；不声称已消除所有调度波动。
保留接收端显式恢复及软件回退，仍需用户在同一真实场景复测流畅度和闪烁。

Windows 完整检查通过；硬件 420/444 直接纹理输入及主动恢复通过，14 条
合成流（含硬件恢复后缀、硬件和软件码率调整序列）经 FFmpeg 独立解码无错误。
