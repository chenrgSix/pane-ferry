# IDEA 原生弹窗验证与端到端延迟（2026-10-25）

新版扩展已在用户重新登录后的真实 GNOME 会话中运行，返回 `bridge_version:3`（扩展包版本 2）。实际 IDEA Git 右键菜单和小分支提示均以无标题栏附属窗口呈现，源坐标与 Mac 窗口几何匹配。主菜单经过 60 次有效打开、绘制和关闭测量：中位数 **234.204 ms**，最近秩 P95 **277.494 ms**。仍有一次 **1081.746 ms** 的有效长尾，保留在统计中，不能宣称整体卡顿已解决。

这次没有同一路由、同一 IDEA 场景的旧版本基线，因此不能据此声称零复制或窗口树修复改善了总体延迟。此前的 GTK 标记窗口结果不是 IDEA 的可比基线。

## 环境与方法

- Ubuntu GNOME 50.1，GStreamer 1.28.2；IDEA 安装构建 `262.10968.63`。Mac 为 macOS 27.0.1（26A434）。
- 正式 Agent 和 WindowHost 对应 `f158a34`；Agent SHA-256 为 `844176fe3d45216ee56b3475196e951a998c43efebd24861f708ecc8643dd202`，WindowHost 为 `de1f1e7674a089600d9738c2ced14b59fc1ec993cb4209a68e7db7cb0eb8d178`。Mac 主应用严格签名校验通过。
- 使用现有配对 QUIC 通道，目标 `10.0.1.66:42424`，Mac 路由接口为 `utun4`。这是本次实际使用的隧道路由，不能称为直接局域网基准。
- 正常产品接入创建虚拟输出并采用 2× 密度；主画面 2800×2000 像素，逻辑尺寸 1400×1000。菜单为 554×1102 像素、277×551 逻辑单位。探针不另指定测试分辨率，不把接入前的源 DPI 宣称为始终未变。
- `PopupProbe.swift` 由当前 WindowHost 源码编译临时副本，仅注入右键和 Escape，不输入文本或执行菜单操作。源端 Agent 没有加入计时钩子，也没有为测试重启服务。
- 选择已观察的 Git 日志提交行，源视频点击坐标 `(1200,1115)`。只接受本次输入后新出现、属于该主窗口、类型为 menu、尺寸匹配已观察菜单的实际绘制。每轮 2 次预热、30 次正式样本，关闭后随机等待 160–260 ms。
- 起点是 Mac `SurfaceView.rightMouseDown`；终点是匹配菜单的 `NSImage.draw` 返回，全部使用同一 Mac 单调时钟。所有有效样本均为 H.264、VideoToolbox 硬件解码、无边框、不成为键盘主窗口。

各阶段分位数不可直接相加。round 4 的第 29 次触发（含预热编号）耗时 1081.746 ms，其中 1039.717 ms 在响应帧到达 Mac 前。该阶段包含输入传输、IDEA 处理、采集等待、临时流/编码器启动、编码及返回传输；现有探针不能把长尾归因于其中单一环节。Agent 测试后仍 active、NRestarts=0，日志没有本次期间的错误输出。

本结果不包含键盘/鼠标硬件扫描、macOS 最终合成、显示扫描或面板响应，也不代表打字、滚动等操作延迟。

## 保留的失败和预备轮次

- round 1：预览成功，但关闭后已有另一个提示浮层，正式测试被前置检查拒绝；未计入。
- round 2：旧探针得到 30 次样本，中位数 212.812 ms、P95 266.817 ms；事后核对全部匹配主菜单。作为预备数据保留，未混入严格探针统计。
- round 3：旧探针把两个 136×64 的提示浮层误认成菜单响应，其中一次发生在预热、一次在正式采样。**整轮拒绝**，没有只删除较快样本后拼接结果。
- 因此在 `a73524a` 中要求匹配观察确认的像素尺寸，并排除输入前已存在的子窗口。round 4 实际忽略了一个其他提示浮层，30 次目标菜单仍完整测得。
- round 6：重新接入时已有小提示浮层，前置等待没有满足“仅主窗口”条件，操作者停止探针；零样本，未计入。等待脚本的 `source size not ready` 是概括性异常，实际尺寸已就绪，阻止开始的是已有浮层。
- 单独的小提示图像检查以显式 stop 结束，属于观察会话，不计作性能轮次。

探针修正仅影响测试相关性判断，不按 IDEA 名称或固定尺寸修改产品行为。产品仍根据合成器提供的通用父子关系、类型和几何展示。

测试结束已断开临时控制连接，IDEA 进程及窗口继续运行，`controlled:false`。本机另发现历史 IDEA 缓存入口包含旧 WindowHost；已打开经过校验的新版主启动器。应从新版主启动器重新连接，由按二进制摘要区分的缓存机制生成新版入口。
