# PipeWire 裁剪与颜色转换合并（2026-10-24）

## 结果

原路径先将窗口区域复制到紧凑 BGRx 图，再由编码管线转换成 I420。新路径共享 PipeWire 原缓冲，把经过 HiDPI/窗口边界校正的区域显式交给 GStreamer 转换器，直接生成 I420。缓存、去重与编码器共享转换结果，不再分配或复制中间裁剪图。

远端为 Ubuntu 26.04.1、Intel i5-13400，GStreamer/core/videoconvertscale/x264 插件均为 1.28.2。以蓝色背景中的红色区域验证时，普通 `videoconvertscale` 加 crop 元数据仍输出蓝/红混合的亮度值；显式 `converter-config` 源区域后只输出红色区域。不能用当前上游 main 的自动 crop 支持推断已安装版本行为。

转换采用异步有界队列，控制线程只做边界校验、缓冲引用和非阻塞提交。输入最多保留处理中的一帧和排队的一帧，完成后唤醒控制循环；转换结果保留最新一帧。通过 parent-buffer meta 保持源缓冲租约，防止原 sample 释放后被 PipeWire 缓冲池提前复用。转换结束后，缓存和慢速编码仅持有独立 I420 输出。

## 交错基准

同机 release Rust 测试直接调用实际转换器和编码器，比较旧版单次映射/逐行裁剪复制与新路径。两者使用相同源像素、区域、x264 ultrafast/zerolatency、4 个 slice 线程、60 fps 时间戳、码率和 QP 上限。每个尺寸 4 轮，顺序 AB/BA/AB/BA，每种每轮 5 帧预热、40 帧计时，共 160 个计时样本。所有轮次及样本均保留。

计时从已经收到的原始 BGRx 缓冲开始，到该帧 H.264 编码输出结束；新路径包括等待转换结果的时间。**不包含应用重绘、PipeWire 到帧等待、QUIC、Mac 解码或屏幕呈现，不是端到端延迟。**

| 有效尺寸 | 旧路径中位数 / P95 ms | 新路径中位数 / P95 ms | 中位耗时下降 |
|---|---:|---:|---:|
| 1280×720 | 2.726 / 3.634 | 2.594 / 3.206 | 4.9% |
| 2940×1618 | 13.647 / 15.455 | 11.827 / 14.024 | 13.3% |
| 4000×2000 | 23.553 / 27.139 | 19.722 / 23.418 | 16.3% |

2940×1618 四轮中位耗时分别下降 8.9%、9.3%、17.8%、13.1%；4000×2000 四轮均改善。1280×720 有一轮基本持平，因此小尺寸收益不稳定。机器保留用户既有后台负载，没有修改 CPU 频率或电源策略。

在 2940×1618 下，旧同步裁剪复制中位数为 2.166 ms；新非阻塞提交为 0.0034 ms。后者只是控制线程交接耗时，实际颜色转换仍在后台执行，已计入上表总耗时，不能将其宣称为完整采集耗时。

2940×1618 每帧减少约 19.0 MB 的 BGRx 中间分配/复制；4000×2000 减少 32 MB。I420 转换输出仍然存在；缓冲池、编码器、网络也可能有各自的内存操作，不宣称全链路零拷贝。

## 验证与边界

- Ubuntu Agent：34 项测试通过（显式运行原生测试，排除独立基准）；release 构建通过。包括真实 GStreamer 转换、源缓冲释放、异步积压上限、完成唤醒、旧几何失效、两种编码器和首帧失败回退。
- 偶数尺寸 I420 有效像素逐字节匹配旧裁剪/转换路径；奇数尺寸的亮度及非边界色度匹配。奇数边界最后一行/列色度可能不同，因为旧路径先补 RGB 黑边再下采样，新路径在转换时补边；差异被限定在对应 4:2:0 边界，不涉及缩放或丢失窗口像素。
- 隔离 GNOME/Wayland：源 2×，1470×802、900×700、900×600、1470×900、700×500 逻辑窗口均收到相应 2× H.264 帧；多次 resize、同进程/内容/会话重连、私有显示器回收通过。未操作用户应用或真实桌面输入。
- macOS `bash scripts/check.sh` 完整通过：Rust 工作区、Python/JS 单元检查、前端构建、Swift 构建、真实 QUIC/H.264 接收、剪贴板与重连门禁。新增代码再经格式检查和 Agent 单元测试通过。额外执行的严格 Clippy 仍被四项既有告警阻止：`video_qos::target`、`wayland::compositor_id`、`main.rs` 相同分支和旧 `video.rs` 常量断言；本次未修改这些无关代码。
- 未部署新二进制、未重启用户 Agent。结束检查时原服务 PID 2258536、NRestarts=0；本次临时构建和隔离测试不代表真实 IDEA/Mac 会话端到端验收。
