# 60/90 fps 与鼠标回显实机测量

2026-10-23，源码 `03f40b1`。Mac 为 Mac16,12、macOS 27.0.1，当前屏幕报告最高 60 Hz；Ubuntu 为 26.04.1、Intel Core i5-13400。两端使用 H.264 和真实 QUIC 连接。Mac 到 `10.0.1.66` 的路由经过 `utun4`，MTU 1360；本次没有核验虚拟网络底层是否 P2P，也没有测物理 IP 直传。

为保留用户正在运行的 ChatGPT，测试在 Ubuntu 的独立 Agent、Xvfb 和临时配对节点内运行。X11 测试窗口每 8 ms 请求一次局部画面更新，日志记录约 117.9 次更新/秒。Mac 使用当前 WindowHost 源码编译临时副本，只增加计时钩子；输入、QUIC、H.264 解码、帧合并、反馈和 AppKit 绘制仍走产品路径。没有重启 Ubuntu 桌面、Agent 或 ChatGPT。

每个尺寸按 60→90→60→90→60→90 的顺序测试，每轮切换后预热 1.5 秒，再记录约 5 秒。接收帧率统计进入窗口的不同 `frame_id`，绘制帧率统计真正完成 `NSImage.draw` 的不同 `frame_id`。数字是每秒实际帧数，不是配置上限。

| 画面尺寸 | 上限 | 三轮接收 fps | 三轮绘制 fps |
| --- | ---: | --- | --- |
| 900×700 | 60 | 58.4 / 58.5 / 58.5 | 58.4 / 57.9 / 57.7 |
| 900×700 | 90 | 74.8 / 66.2 / 68.2 | 59.6 / 57.4 / 59.0 |
| 2940×1604 | 60 | 40.2 / 40.4 / 40.1 | 39.6 / 40.4 / 40.1 |
| 2940×1604 | 90 | 39.4 / 39.4 / 39.4 | 39.4 / 39.4 / 39.4 |

900×700 时，90 档多接收了一些帧，但这块 60 Hz 屏幕没有多绘制出相应帧。2940×1604 时两档都约 40 fps；绕过 QUIC、在 Ubuntu 本机读取同一隔离 Agent，60 和 90 档分别为 39.8 和 39.9 fps，说明主要上限位于发送端的窗口采集/编码输出链，不能归因于 Mac 绘制或 QUIC。此测量尚未把采集与编码各自耗时拆开。

输入起点是临时 Mac WindowHost 调用真实 `SurfaceView` 的鼠标事件处理函数，终点是相应黑白画面标记完成 `NSImage.draw`；每次都核验远端窗口收到事件。900×700 下 18 次点击均到达，延迟中位数 65.0 ms、P95 107.4 ms；2940×1604 下 18 次均到达，中位数 109.6 ms、P95 154.8 ms。两组点击均在 60 档进行。

纯移动另用 900×700 窗口分别在 60 和 90 档测三轮，每轮 18 次，共 108 次，全部收到正确坐标并完成对应画面绘制：

| 上限 | 三轮移动中位数 ms | 三轮移动 P95 ms | 合并 54 次中位数 / P95 ms |
| --- | --- | --- | --- |
| 60 fps | 65.4 / 73.5 / 66.9 | 94.4 / 133.9 / 100.3 | 66.9 / 99.3 |
| 90 fps | 61.0 / 76.2 / 60.7 | 86.2 / 138.7 / 76.6 | 63.0 / 93.6 |

此路径没有固定的 200 ms 等待；90 档的移动延迟与 60 档相近，不能依据这些样本断言有稳定改善。计时不包含物理鼠标采样、macOS 合成和屏幕扫描，不是光子延迟。测试窗口是独立 X11/Xvfb 会话，并非用户的 GNOME Wayland、飞书或 ChatGPT；这些实际应用的持续帧率仍需在不影响任务时另测。

测试初期发现 Ubuntu 已安装新版 Agent，却仍运行旧版 QUIC 网络组件。旧组件不允许新版 `video.configure`、`video.feedback` 消息；临时配对测试约 5 帧后连接关闭，Mac 反复重连，得到的约 3 fps 数字因此作废。用同一源码构建新版 Linux 网络组件后，临时 QUIC 测试稳定完成上述轮次。正式 Ubuntu 网络组件随后以该二进制替换并仅重启 `paneferry-network.service`；安装后 SHA-256 为 `bf196173a1d60cfa97323c75f11b1ffdc87ce2e2b0c9db901898f856829e9d83`，旧版备份在 `~/.local/bin/paneferry-network.before-video-qos-20261023`。原 Agent PID 443119 和 ChatGPT PID 14785 未变化。原配对 Mac→Ubuntu 连接重新握手后，`video.enable`、`video.configure`、`video.feedback` 和 `session.list` 依次通过；这证明正式业务协议恢复，但不是对原 ChatGPT 窗口的视频实测。
