## 条件和测量边界

- 同一地址 `10.0.1.66`，Mac 路由为 `utun4`；4 次 ICMP RTT 平均 19.119 ms，范围 18.410–19.904 ms。
  这是当前隧道路由，不能与历史 `192.168.1.254` 物理局域网的 69.4 ms 直接比较。
- 源端自有 GTK Wayland 夹具，1470×809 像素、1×、每 33 ms 小块动画；输出上限 30 FPS。
  H.264 编码质量配置不变，Mac 硬件解码；本轮两版均使用当前 Mac 宿主代码，显示区 1445×793 点、屏幕 60 Hz。
- 8 轮顺序为旧、新、新、旧、新、旧、旧、新。每轮按键与点击各预热 2 次，再各采样 30 次。
  全部 480 个正式样本核对源输入、对应视觉计数、源绘制尺寸、1× 缩放、协商帧率和硬件解码；没有失败轮次被丢弃。
- 正式比较只使用未插桩 Agent 和原网络服务二进制的临时隔离实例，复用配对但不改生产地址。
  SSH 只管理测试和取回日志，测试输入和视频走 QUIC。正式采样期间没有并行编译或门禁测试。
- 起点是 Mac 输入处理函数，终点是对应 CVPixelBuffer/IOSurface 的 renderer 缓冲身份匹配。
  不包括键盘硬件、屏幕扫描或面板响应，不能称作高速摄影测得的 input-to-photon。
- 早前 102.3→93.1 ms 的对照使用不同版本和 1460×801 点显示区；本轮应比较自己的 107.2→93.6 ms。

## 改动与诊断证据

普通原生 Wayland 窗口的周期 `scope` 查询进入现有后台 RPC 工作线程；主循环非阻塞消费已完成的快照。
后台完成通过共享唤醒通知主循环；输入等前台 RPC 在后台查询间优先处理。
窗口尺寸变化、恢复连接会丢弃过期快照，窗口身份和进程存活校验保留。
场景模式仍保留所需的 scene/list 查询；普通窗口只请求 scope。没有按应用名分支，也没有改变 FPS、分辨率、QP 或 GOP。

另测两轮插桩诊断，各 40 个正式响应，并加入两端网络边界计时。诊断 P50 为 107.837→95.692 ms，
P95 为 151.204→127.010 ms；这些数值不混入上面的正式统计。

| 诊断项 | 基线 P50 / P95 ms | 新版 P50 / P95 ms |
|---|---:|---:|
| 去重后的主循环元数据扫描调用 | 6.719 / 16.885 | 0.019 / 0.035 |
| 匹配响应的额外发布等待 | 5.774 / 19.319 | 0.504 / 1.014 |
| 全部发布尝试的额外等待 | 1.136 / 18.597 | 0.574 / 4.063 |
| 输入状态查询 | 0.001 / 0.183 | 0.001 / 0.149 |
| 解析与硬解 | 2.621 / 3.083 | 2.391 / 3.056 |
| 编码 | 1.512 / 2.217 | 1.478 / 2.220 |
| 双向传输与桥接残差 | 21.340 / 24.715 | 21.464 / 24.757 |

额外发布等待定义为 `publish − max(本次最早允许发布时刻, 最终所选样本 ready)`，截断负值为零。
它不包括正常 30 FPS 限速的剩余等待，也不是硬 deadline 违约。
全部发布尝试分别为 232 和 244 次；两版均未发现“已有更新输入计数的完成帧，却发布旧计数帧”。
输入状态查询本次没有出现此前推测的 6 ms 阻塞，因此未继续修改该路径。
各项为独立分位数，不能相加得到总延迟分位数。

新版其余阶段的 P50：Agent 收到输入到 GTK 回调 16.53 ms、回调到绘制 3.19 ms、
绘制到首次响应 raw pull 20.01 ms、raw pull 到首次 I420 pull 3.38 ms、I420 pull 到发布 16.44 ms。
这些边界包含各自的调度等待，不能全部当作 CPU 运算时间。

## 大关键帧和 Mac 显示阶段

两轮诊断全部网络帧中，23 个关键帧的实际 H.264 负载中位数为 146,590 字节，
读取首字节后到完整包的 P50/P95 为 **18.228/30.115 ms**；636 个非关键帧为 **0.034/1.584 ms**。
这包含预热、启动和普通动画帧，不能当成 23 个正式输入的端到端分布。
新版正式诊断响应中仅 1 条命中关键帧：负载 137,727 字节、端到端 134.437 ms、
混合残差 41.003 ms，其中接收首字节后还等了 18.211 ms 才读完整包。

新版 40 条响应中，完整 QUIC 包到 Mac 完整协议行的 P50/P95 为 **0.356/0.792 ms**，
Agent 写完到本地网络发送开始为 **0.081/0.150 ms**。关键帧样本的本地接收后交付为 2.134 ms。
当前证据支持继续研究大包传输等待，不支持将主要成本归咎于 Base64 或本地 bridge；
本次没有凭单一相关性修改拥塞控制、GOP、画质或桥接缓冲。

Mac 解码完成到 renderer 匹配的 P50 为 **9.076 ms**，可继续拆为：
解码回调到主线程选帧 0.070 ms，选帧到提交返回 0.173 ms，提交到 transaction completion 2.630 ms，
completion 到 renderer 匹配 6.323 ms。completion 投递回主线程仅 0.040 ms。
这些也是各自的中位数，不要求精确相加；transaction completion 不是实际 presentation。
有前一次失败查询的 39 条样本，其查询观测窗口 P50 2.080 ms、P95 3.859 ms、最大 8.424 ms；
不把观察到的匹配时间当成精确 VSync 时间。

## 身份、时间轴与验证

诊断记录现在分别保留 producer-ready、raw pull、I420 pull 的样本 ID。
首个响应、最终选帧和实际协议 `frame_id` 分开记录，避免用连号猜补；新版最慢五条见 JSON。
输入 ID 为 `轮次/input-count`，由夹具计数构成，不是 RWP 自带 ID。
原始压缩包保留纳秒时间，session ID 用一致别名替代，不含视频、剪贴板、用户应用内容或配对凭据。
同一 Mac 使用 uptime，Linux 使用 CLOCK_MONOTONIC；只在同端做差。
跨端混合残差通过扣除同端区间得到，不是单向网络时间。QUIC 本地 write 完成不是远端收到。
