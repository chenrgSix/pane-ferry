# GNOME 桥接 5：激活、输入延迟与复测

2026-10-28 已通过运行中的 GNOME RPC 确认桥接版本 **5**，不再需要为本轮更新重新注销。保留通用的就绪调用快路径 `4a670f9`；采集交接候选 `1da32a5` 在两组有效对照中均未显示稳定收益，已由 `b0319c1` 撤回。正式 Agent、网络程序和 Mac 产品二进制未替换。

保留路径的两组有效正式样本共 **480 条**，P50 **72.786 ms**、P95 **123.847 ms**；低于 100 ms 为 **427/480**，超过 200 ms 为 **3 条**，最大 **467.553 ms**。仍有长停顿，没有达到消除卡顿或稳定 P95 低于 100 ms 的目标。

[完整统计与各组最慢五条关联](2026-10-28-bridge5-input-latency.json)、[脱敏原始时间线](2026-10-28-bridge5-input-latency.raw.jsonl.gz)包含有效对照、尺寸变化导致的无效对照、预检、候选/保留路径诊断和验证记录。

## 条件与归因边界

- 两版均使用同一个已加载桥接 5 的 GNOME 会话，地址 `10.0.1.66`，Mac 路由 `utun4`。测试前 4 次 ping 平均 6.421 ms；收尾时 4 次平均 35.362 ms，其中一次为 121.087 ms。网络存在明显尖峰，不能将每个慢输入都归为代码回归。
- 自有 GTK X11 计数窗口，输出 **1470×809、1×、上限 30 FPS**，每 33 ms 更新小块动画。X11 backing 为 2940×1618、2×；收到的输出保持 1×。编码质量、GOP、网络程序和硬件解码一致。用户应用保持运行，没有并行编译、性能剖析或门禁与正式采样重叠。
- Mac 显示区 1454×798 点，屏幕 60 Hz。每轮预热按键、点击各 2 次，再正式各 30 次。每组各版 240 条；首组顺序旧、新、新、旧、新、旧、旧、新，固定尺寸复测使用反向顺序。
- 第二组有效比较使用固定显示区探针 `0adcdfb`，固定为与首组相同的 1454×798 点，并在每次注入前检查本地/源端几何。首组所有轮次的实际显示区也一致；两组各自结果单列，合并值仅用于概览。
- 起点是 Mac SurfaceView 输入函数，终点是 AVFoundation renderer 对应显示缓冲身份匹配；排除建立连接、首次解码分配、外设、屏幕扫描和面板响应。不是高速摄影测得的 input-to-photon。
- **这不是同轮桥接 4/5 A/B**。重启前后网络、桌面会话、用户负载和 Mac 显示区发生变化，不能直接用 10/27 的 131.056 ms 减去本轮结果，宣称差值全部来自 GNOME 优化。

## Agent 对照与撤回决定

| 有效比较 | 基线 P50 / P95 | 采集交接候选 P50 / P95 |
| --- | ---: | ---: |
| 首组，240 条/版 | 68.163 / 102.822 ms | 69.714 / 129.037 ms |
| 固定显示区反向复测，240 条/版 | 75.583 / 131.031 ms | 75.619 / 148.503 ms |

两组汇总，基线/候选 P50 为 **72.786 / 72.782 ms**，P95 为 **123.847 / 142.072 ms**。候选没有中位数收益，两组 P95 都更高，因此撤回这一尚未部署的修改；这不等于已经证明每个尖峰由该修改导致。保留源码的 Agent/后端运行时代码与正式基线 `0ac233c` 一致。

另有一整组反向复测在最后一轮从 1454×798 变为 1460×801 点，被预先设置的几何检查拒绝。八轮全部记录（包括 674 ms 尖峰）保留，标注为无效比较，不混入上述 480 条/版；有效组没有删除尖峰或失败输入。

## 保留路径的独立诊断

另取 40 条插桩诊断，端到端 P50 **61.736 ms**、P95 **103.727 ms**。它与正式统计分开，不作为代码收益的重复证明。各阶段分位数独立，不能直接相加。

| 区间 | P50 | P95 |
| --- | ---: | ---: |
| Agent 收到 → 开始分发 | 0.024 ms | 3.252 ms |
| 输入注入函数 | 2.100 ms | 3.722 ms |
| Agent 收到 → 应用收到输入 | 3.209 ms | 6.694 ms |
| 应用收到 → 绘制 | 1.306 ms | 13.357 ms |
| 绘制 → 首张响应采集帧完成 | 23.630 ms | 36.741 ms |
| 最终帧读回调用（采集区间内部） | 6.421 ms | 13.601 ms |
| 读回线程 CPU 时间（内部） | 0.678 ms | 1.124 ms |
| 最终原始帧完成 → 发布 | 0.345 ms | 5.821 ms |
| 发布 → 开始编码 | 0.020 ms | 0.038 ms |
| 补边、转换及编码调用整体 | 5.257 ms | 6.645 ms |
| 传输、桥接、序列化等混合残差 | 11.492 ms | 22.942 ms |
| Mac 完整消息 → 硬解完成 | 2.333 ms | 4.206 ms |
| 硬解完成 → 主线程选帧 | 0.064 ms | 0.273 ms |
| 选帧 → renderer 缓冲匹配 | 8.414 ms | 16.843 ms |

输入注入约 2.1 ms，应用收到输入约 3.2 ms；主要剩余区间是绘制到响应采集帧完成约 23.6 ms，读回墙钟约 6.4 ms、线程 CPU 约 0.68 ms。先前候选诊断中约 35 ms 的采集值也保留在 JSON，不能冒充当前保留路径的同批统计。

混合残差为 `(Mac 收到 − Mac 写出结束) − (Linux 最终帧写出结束 − Agent 收到输入)`，扣除完整 Agent 区间；它不是纯网络或跨机器直接相减的单向时延。正式样本没有 Linux 插桩，首张读回/I420 ID 和内部时刻留空；独立诊断才包含首张响应读回 ID、最终读回、RWP 帧关联和完整同机时间线。
