# 输入与采集调度：1×、30 FPS

本轮保留采集交接优化 `1da32a5`，同轮正式对照的 P50 **135.121 → 131.056 ms**，减少约 **4.066 ms / 3.0%**；P95 **176.697 → 175.095 ms**，变化较小。没有达到大幅降低延迟的目标。更直接针对输入等待的 GNOME 优化 `4a670f9` 已安装扩展文件，但运行时仍为桥接 4，须用户重新登录后确认桥接 5，再测实际收益。

[统计与最慢五条关联](2026-10-27-input-capture-scheduling.json)、[脱敏原始时间线](2026-10-27-input-capture-scheduling.raw.jsonl.gz)保留正式、诊断、预检和失败记录。

## 条件与边界

- 地址 `10.0.1.66`，Mac 路由 `utun4`；首轮前 4 次 ping 平均 27.268 ms，全部试验后为 17.359 ms，说明期间网络也有变化，不能假定每条响应的 RTT 相同，也不能与历史不同时间的 111.42 ms 或物理局域网结果直接相减。
- 自有 GTK X11 计数夹具，输出 1470×809、1×、上限 30 FPS；源端保留 2940×1618、2× backing，每 33 ms 更新一小块动画。两版编码质量、GOP、网络二进制和硬件解码保持一致。没有提高帧率或改变用户应用缩放。
- Mac 显示区 1447×794 点、60 Hz。每项正式试验均按旧、新、新、旧、新、旧、旧、新交错运行；每轮预热按键、点击各 2 次，再各取 30 条，共 240 条/版本。所有轮次和尖峰保留；未并行编译、性能剖析或运行门禁。
- 起点为 Mac SurfaceView 输入函数，终点为 AVFoundation renderer 返回对应显示缓冲的身份匹配，不含外设、屏幕扫描和面板响应。两端使用独立单调时钟；独立阶段分位数不能相加。
- 正式 Agent 无 Linux 插桩，未知的首张原始帧、I420 ID 和 Linux 内部时刻留空，没有用最终帧 ID 代替。另做诊断以视觉计数关联输入、首张响应读回、最终读回和 RWP 反馈帧。

## 两项正式试验

| 试验 | 基线 P50 / P95 | 候选 P50 / P95 | 处理 |
| --- | --- | --- | --- |
| 减少输入范围重复查询 | 140.616 / 196.243 ms | 149.834 / 190.620 ms | 未降低中位数，`e8ef8df` 已由 `710dcc1` 撤回 |
| 采集身份交接 | 135.121 / 176.697 ms | 131.056 / 175.095 ms | 保留 `1da32a5`，收益有限 |

第二项四个相邻时间块的中位数均改善，但尾部变化不一致，不据此宣称卡顿已经解决。两项试验发生在不同时间，必须各自比较自己的基线。

采集交接保留工作线程在读像素前、后的真实 XRES 所有者检查；主线程使用可信发现阶段固定的进程身份，继续检查进程启动时间、窗口范围、epoch、尺寸及控制者刷新，避免再用输入连接重复查询 X Server。没有将未验证的身份缓存当作读像素授权。

私有 Xvfb 的服务器占用回归证明：已完成且已验证的画面可以在 X Server 被占用时交付，不再因此阻塞输入主循环。普通交接查询的中位数原本很小；诊断中部分等待还会移到后续 DAMAGE 重置，不能把每段缩短简单相加为端到端收益。

## 诊断与下一步

采集交接另取 40 条/版本诊断，P50 **126.711 → 130.270 ms**，P95 **183.077 → 168.592 ms**。诊断中位数没有改善，不能将诊断组当作正式收益的重复证明。以下为候选诊断的独立阶段统计：

| 区间 | P50 | P95 |
| --- | ---: | ---: |
| Agent 收到 → 应用收到输入 | 36.740 ms | 65.731 ms |
| 应用收到 → 绘制 | 1.950 ms | 33.854 ms |
| 绘制 → 首张响应原始帧完成 | 34.857 ms | 67.533 ms |
| 最终读回调用（包含在采集区间内） | 3.770 ms | 28.533 ms |
| 最终原始帧完成 → 发布 | 0.532 ms | 5.151 ms |
| 补边、转换及编码调用整体 | 5.470 ms | 7.129 ms |
| 传输、桥接、序列化混合残差 | 18.539 ms | 34.421 ms |
| Mac 完整消息 → 解码完成 | 2.112 ms | 3.912 ms |
| Mac 解码 → 主线程选帧 | 0.064 ms | 2.318 ms |
| 选帧 → renderer 缓冲匹配 | 9.673 ms | 17.088 ms |

混合残差按 `(Mac 收到 − Mac 写出结束) − (Linux 最终帧写出结束 − Linux 收到输入)` 计算，扣除了完整 Agent 区间，首张到最终响应帧之间的等待没有漏进传输残差。它仍不是纯网络或单向网络时延。

输入 RPC 仍明显受 GNOME 桥接影响。源码中的无条件 `await ensureOutput()` 即使没有输出初始化工作，也会让出 Shell 事件循环。桥接 5 在 X11 和已就绪的 Wayland 输出上直接答复；创建、恢复、取消输出仍保持异步流程，所有者、锁屏、范围和弹窗焦点检查不变。这项优化只有 Node 生产方法回归，尚无加载新版后的端到端结果；扩展包版本 4 和桥接版本 5 不能仅凭文件安装宣称已生效。
