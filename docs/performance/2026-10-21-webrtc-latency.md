# 2026-10-21 WebRTC H.264 对照

**决定：保留 `experiment/webrtc-h264` 实验分支，默认和当前安装仍使用 SSH H.264，不替换。**
WebRTC 媒体轨道已实现并通过基础功能测试，但这次对照没有稳定的整体延迟收益；追加复测还出现一次媒体已连接却未完成有效回显的失败。

## 环境与方法

- Apple Silicon Mac / macOS 27.0.1，Ubuntu 26.04.1 x86_64；同一源码 `02890ce` 分别强制 `ssh` / `webrtc`，不拿历史测量充当本次控制组。
- SSH 目标固定 `10.0.1.66`；两端 WebRTC 绑定 `10.0.1.253` / `10.0.1.66`。每个成功 WebRTC 样本均核验实际 UDP 候选对，走与 SSH 相同的 utun4 路径，未顺便切到另一条物理 LAN。
- 2940×1612、2560×1664 保持原像素尺寸；相同 MIT-SHM / XDamage 采集、OpenH264、VideoToolbox 硬件解码和 AppKit 绘制。媒体直接使用原编码 AU，没有第二次压缩。
- 编码参数保持 screen / low、I420、`bitrate=clamp(width*height*3, 2M, 24M)`、max-bitrate 为两倍、GOP 60、4 线程、禁止跳帧、QP 上限 28；采样最短间隔仍为 33ms。
- 动态场景每种尺寸各两对，交换运行顺序；静止场景一对。每次交错测方向键、文字提交和点击，各 30 次；另各预热 2 次。十次成功运行共 **900 个有效样本、60 个不计入统计的预热样本**，没有剔除成功组里的慢样本。
- 动态夹具只有一个小块持续更新，主体为文字和图形；不等同于全屏视频或整页快速滚动。
- 起点为真实产品 SurfaceView 输入函数，终点为包含对应输入标记的 AppKit 绘制完成。每次核对输入类型、计数、画面标记、尺寸和实际硬件解码。此终点不含键盘硬件扫描、系统事件获取、拼音组合、macOS 最终合成和物理面板响应。

两端只取各自单调时钟的差值。传输段为整个往返扣除两端内部处理后的剩余时间，包含 SSH 输入、媒体传输、协议及缓冲；不是单向纯网络时延。详细方法见 [测量脚本说明](../../tests/performance/README.md)。

## 合并结果

单位 ms；P95 使用最近秩。每种传输的动态场景各 180 个样本，静止场景各 90 个。

| 场景 | SSH 中位数 / P95 | WebRTC 中位数 / P95 | SSH / WebRTC 平均值 |
| --- | ---: | ---: | ---: |
| 2940×1612 持续更新 | 84.16 / 132.16 | 86.39 / 112.38 | 90.68 / 88.16 |
| 2560×1664 持续更新 | 81.16 / 103.30 | 80.05 / 107.72 | 80.10 / 80.20 |
| 2560×1664 静止后输入 | 60.98 / 78.12 | 67.69 / 118.37 | 61.51 / 73.97 |

2940 动态组尾延迟有改善，中位数略慢；2560 动态基本持平，静止组变慢。当前数据不能支持“换 WebRTC 就会明显更跟手”，也不能将本次静止组差异推广为所有设备上的固定开销。

## 追加复测失败

为确认静止组差异，追加反向顺序的 WebRTC → SSH 测试。WebRTC 在已到达 connected 状态后，接收端连续发出 16 次关键帧恢复通知，最终报媒体失败，未产生有效的输入回显样本；对应 SSH 运行尚未开始。该次不构成完整延迟分布，**单独保留为失败记录，不作成功样本或静默回退成功处理**。

日志见 [失败原始输出](2026-10-21-webrtc-failure.txt)。该记录能确认媒体恢复未成功，尚不能单凭这些通知确定是 UDP 丢片、重组期限、发送突发还是其他实现问题。自动模式的独立建立失败/中途停流回退已经通过，但回退能力不等于 WebRTC 稳定性达标。因此没有再次运行直到成功，也没有降低尺寸、码率或画质来掩盖问题。

## 功能与画质验证

- 两个平台的 C++ wire / receiver 测试通过：SEI、CRC、乱序、重复、序号回绕、NACK 重传、超时 PLI、IDR 恢复及缓存释放。
- 真实 ICE / DTLS-SRTP / UDP loopback 通过，包含 350KB 分片、第二窗口重新协商及大小限制；17 个实际 Agent H.264 AU 经媒体轨道后，原有 NAL 每字节一致。
- 新版普通 Agent 的真实 WebRTC 输入、641×483 奇数尺寸、连续 P 帧、动静态重连、显式回退 SSH 通过；现有进程边界、中文/emoji、多行及主动双向剪贴板回归通过。
- 18 个实际视频 AU 经 Mac VideoToolbox 硬件解码通过，涵盖 P 帧、响应像素、奇数尺寸裁边、重连及非法 NAL 拒绝。HiDPI 和原 SSH 视频回归通过。
- 自动模式在故意不可达媒体地址下回退 SSH 通过；中途故意丢弃媒体回调时，同一窗口从 WebRTC 恢复为 SSH 并继续响应输入。故障注入仅存在于临时测试源码副本。
- Mac Rust 测试 33 项通过、4 项默认忽略，fmt / clippy 通过；Swift release 构建和独立实验包的 runtime / 许可证打包通过。没有以这些结果代替 CI 或完整应用验收。
