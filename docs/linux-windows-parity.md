# Linux 与 Windows 功能对齐

目标：让 Linux 在现有平台能力范围内尽量提供与 Windows 相同的发布、接收和操作功能。
基线为远端 `02ccb82` 与 Linux 桌面补齐提交 `5502183`。功能以协议、像素、输入和生命周期验证为准。

| 功能 | Linux 状态 | 本轮工作 |
| --- | --- | --- |
| 完整桌面、光标、4K/竖屏/宽屏 | 已实现并更新本机 | 已有隔离桌面解码验证，继续保留回归 |
| 应用发现、启动、接管、设备级接管 | 已有 | 对照 Windows 的主窗口过滤、身份与重复接管 |
| 原生 Wayland 应用及弹窗聚合 | 可选场景 | 保留现有隔离、输入和重连能力 |
| XWayland 应用及跨协议弹窗聚合 | 已实现，需桥接版本 7 | 100%/200% XWayland 菜单、隔离、重复控制、重连及双向模式切换通过；跨协议 transient 关系另有单元检查 |
| 420 / 444 atlas v1、v2 协商 | 已实现发布和接收 | 平台共用 atlas 布局；PipeWire 原生 Y444 和 X11 BGRx 均在降采样前保留色度；420 保留原有 GPU 自适应路径 |
| 系统输出音频发布 | 已实现 | Pulse/PipeWire 输出 monitor、共享 Opus 编码器、独立订阅、最后订阅关闭清理 |
| 系统声音接收与播放 | 已实现 | GTK 每设备播放器，共用 Rust PLC/抖动缓冲；默认关闭、断开画面后可继续收听 |
| 输入、文本、剪贴板 | 已有平台差异 | 保留 Portal/libei 授权与范围检查，列明实际缺口 |
| 视频反馈、码率、按需恢复 | Linux 与 Windows 不同 | 对照连续流、弱网积压和编码器重启策略 |
| 断开/重连、暂停/后台、关闭与会话保留 | 已有 | 每项新增路径执行生命周期回归 |
| Linux GTK 工作台 | 已补桌面、色彩、场景、声音和设备接入入口 | 桌面与场景保持比例；原尺寸显示不调整源窗口；声音独立于画面 |
| 包装、能力声明、升级及文档 | 部分文档仍平台限定 | 仅对实际可用路径公布能力，完成本机更新 |

平台限制不会通过绕过系统授权实现。登录界面、无人登录唤醒、受保护桌面和对任意发行版的保证
不属于 Windows 当前普通桌面功能的可直接移植范围；必要的系统授权和后端差异保留。

进度和各项验证随实现更新；尚未完成的项不能标成已对齐。

## 本轮全色度与接收器验证

- 同一份 Rust 布局实现供 Windows 与 Linux 发布端使用，Windows 原有 BGRA 路径保持数值一致。
- Linux 使用软件编码全色度；这会增加传输像素、CPU 和带宽，不代表全色度比默认 420 更快。默认仍为 420。
- 64×48、641×483、1602×932、2560×1440，BGRx/Y444 输入、v1/v2 共 16 组：原始色度值检查、首帧 IDR/后续 P 帧检查、FFmpeg 独立解码、生产 Linux 接收器解码均通过。
- Linux 接收器另通过四组 Windows 软件/硬件 v1/v2 参考帧；相邻红蓝单像素细线保持可区分。
- 隔离 GNOME：Wayland/v2 与 XWayland/v1 场景的真实 PipeWire→H.264→Linux RGB 解码、弹窗变化、同 PID 外部窗口排除、断开重连和输出清理通过。
- Linux 接收器接受 Windows 的 8-bit 4:2:0 High Profile，同时拒绝不支持的色度、位深、超限 SPS/DPB。完整色彩仍通过 NV12 atlas 承载，不是 H.264 High 4:4:4。
- 真实 GTK + 配对 QUIC 验证：键盘 keysym 回退、固定桌面画布不发送 resize、比例映射、黑边不误点、拖动到黑边释放按钮；既有 IM、文本/图片/文件剪贴板、关联窗口、重连和迟到帧拒绝回归通过。
- GTK 自动接入默认关闭、按设备保存、过滤不可自动接入窗口；每设备串行发起连接，关闭的接收窗口在本次开启期间不反复抢回。最多八个本地接收会话。

全色度在极端画布/高帧率下仍受 GStreamer 原始数据率的有符号整数范围限制；超过范围明确报错。Mac 和 Windows 原生客户端的实际互通需各平台实机验证，当前机器只验证其参考数据与共用 Rust 测试。
