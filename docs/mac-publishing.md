# Mac 发布与 Ubuntu 接收

每个平台安装一个 LAN RemoteApp。管理界面同时提供本机应用共享、远端设备、应用目录和运行会话；平台辅助进程由产品启动。Mac 保留原有 Ubuntu → Mac 的 AppKit 宿主，新增指定窗口发布组件；Ubuntu 安装包同时包含原有 Agent、GTK 管理界面和接收窗口，不需要另装客户端版或服务端版。

## 使用

1. 在 Ubuntu 安装 Linux 包：解压后运行 `bash install.sh`。安装前应保存 Agent 自建虚拟会话里的工作，因为升级会重启 Agent；接入的原桌面进程不由 Agent 结束。安装程序会把旧的临时 systemd 单元替换成持久用户服务。
2. 打开 Mac 的 LAN RemoteApp，使用原有 Ubuntu SSH 配置连接。主机指纹仍严格校验，密码由本机服务的私有配置提供，不新增密钥、系统钥匙串项目或 Mac SSH 登录服务。
3. 在 Mac 明确开启本机应用共享，并允许 LAN RemoteApp 的录屏和辅助功能权限。录屏只支持采集，辅助功能用于输入与窗口操作，两者分别检查。远端不能开启共享或触发系统授权。
4. 在 Ubuntu 应用菜单打开 LAN RemoteApp，或运行 `~/.local/bin/lan-remoteapp`。Mac 建立返回通道后会自动出现在设备列表；选择后读取应用名称、图标和可接管窗口。已安装目录按设备缓存，日常刷新只读取运行状态。
5. 从 Ubuntu 打开 Mac 应用，或连接运行中的窗口。应用继续运行在 Mac 当前登录桌面，也会显示在 Mac 本机。Ubuntu 窗口关闭只断开连接；需要退出 Mac 应用时使用应用自身的退出入口。

若辅助功能列表显示已开启，应用仍提示缺少权限，可点“显示共享组件”，将访达选中的 `RemoteAppNode.app` 添加到辅助功能列表。开发资源目录和打包应用内可能各有一份同名组件，系统可以分别识别它们；应以当前产品显示的那份为准，避免从开发目录手动选择另一份。

Mac 管理窗口的红色关闭按钮会隐藏管理界面，连接任务继续运行；点击 Dock 可再次打开。停止共享会结束本机发布的采集与控制以及返回通道，保留应用进程，也不结束正在接收的 Ubuntu 应用。明确退出 Mac 管理进程会结束其返回连接；再次启动后按已保存配置恢复。

## 连接和身份

Mac 管理服务为每个 SSH 端点独立管理返回任务，使用专用 SSH 进程和 StreamLocal `-R` 转发，把 Ubuntu 用户私有 Unix socket 接到 Mac 发布 socket。没有新增监听 TCP 端口，不要求开启 Mac 的 Remote Login。返回连接不修改或终止原有 SSH 登录 master；网络恢复后独立退避重建。Ubuntu 接收宿主每次重连重新解析所属设备的通道，恢复原会话，不重放输入、剪贴板或启动请求。

设备持久 ID、SSH 地址和登录账号分开处理；设备 ID 不代替 SSH 主机校验。公共 Rust 核心提供带设备和账号归属的会话键、连接代次模型。当前管理连接和凭据继续按主机、账号、端口隔离，预留地址迁移时显式核验设备身份的接口，不自动合并不同地址的信任。Mac 的返回连接、Ubuntu 的目录缓存和窗口宿主各自保留来源设备；切换设备列表不会改变已打开窗口的目标。真实连接两台以上远端的完整并发验收尚未完成。

Ubuntu 的设备记录位于 `~/.local/state/lan-remoteapp/peers/`，目录 0700、记录 0600、socket 0600。每次连接有随机代次；旧连接结束只清理自己的一代，不会删除替代连接或其他设备。Mac 管理 socket 和发布 socket 分开，只有前者允许本机共享及权限操作。发布服务有单实例锁，断开的健康检查连接不会结束服务。

## 采集、输入和剪贴板

Mac 使用 ScreenCaptureKit 的 `desktopIndependentWindow` 过滤，只采集选定窗口；VideoToolbox 输出 H.264，Ubuntu 使用 GStreamer 解码并显示在 GTK 原生窗口。原始帧在编码前合并，编码包保持顺序，尺寸变化和重连从新的关键帧开始。帧和解码像素受限，Ubuntu 在解码前检查 SPS 尺寸。该方向首版需要 H.264 运行组件，没有 PNG 回退。

Ubuntu 使用本机 GTK 输入上下文完成中文预编辑和候选，提交 Unicode 给 Mac。普通按键使用协商后的逻辑键接口，Ubuntu 的 Control 快捷键对应 Mac Command；原来的 Mac → Ubuntu 键码映射不变。指针按所选窗口坐标换算；窗口操作和输入都复核 PID、应用启动时间和所选窗口归属。锁屏、窗口退出和权限变化会停止对应控制与采集。

复制、剪切、粘贴通过自有协议主动执行，无后台剪贴板同步。Mac → Ubuntu 方向的双向文本限制为 8 KiB，PNG、文件和目录合计限制为 8 MiB / 256 项，文件为复制。接收前检查路径、父目录、重复名称和大小；不解压任意归档。复制结果关联请求、设备与窗口，旧请求不能覆盖更新的本机复制操作。原 Ubuntu → Mac 的独立大文件通道和既有上限保持原样。

接收窗口不会再次发布：Mac 按接收应用包身份和受管理 `WindowHosts` 路径排除；Ubuntu 按接收管理进程的 PID、`/proc` 启动时间登记排除运行窗口，并排除本产品桌面入口。过滤不依赖窗口标题。

## 当前验收边界

首版只发布选定的 Mac 主窗口，复杂子窗口、菜单和原生应用焦点争用仍需扩展；不创建独立后台 Mac 图形会话。当前系统权限、真实双机验收进度和回归结果见 [验证记录](validation.md)。隔离 GTK/GStreamer 通过，不代表 ScreenCaptureKit、真实输入法或所有 Mac 应用均已通过双机验收。
