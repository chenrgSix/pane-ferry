# Mac 发布与 Ubuntu 接收

每个平台安装一个 LAN RemoteApp。管理界面同时提供本机应用共享、远端设备、应用目录和运行会话；平台辅助进程由产品启动。Mac 保留原有 Ubuntu → Mac 的 AppKit 宿主，新增指定窗口发布组件；Ubuntu 安装包同时包含原有 Agent、GTK 管理界面和接收窗口，不需要另装客户端版或服务端版。

产品统一使用[QUIC 设备配对](native-transport.md)，无需 SSH 引导；本机共享开关和系统权限独立控制。

## 使用

1. 在 Ubuntu 安装 Linux 包：解压后运行 `bash install.sh`。安装前应保存 Agent 自建虚拟会话里的工作，因为升级会重启 Agent；接入的原桌面进程不由 Agent 结束。安装程序会把旧的临时 systemd 单元替换成持久用户服务。
2. 两端打开 LAN RemoteApp，用一端生成的邀请和地址完成设备配对。一次配对支持双向应用请求，不需要 SSH 登录或返回隧道。
3. 在 Mac 明确开启本机应用共享，通过“允许共享所需权限”允许本机共享组件的录屏和辅助功能权限。组件由系统应用机制在后台启动，两项权限均检查该组件；管理窗口的权限不能代替组件的权限。录屏只支持采集，辅助功能用于输入与窗口操作，两者分别检查。远端不能开启共享或触发系统授权。
4. 在 Ubuntu 应用菜单打开 LAN RemoteApp，或运行 `~/.local/bin/lan-remoteapp`。完成设备配对后，Mac 会出现在设备列表；选择后读取应用名称、图标和可接管窗口。已安装目录按设备缓存，日常刷新只读取运行状态。
5. 从 Ubuntu 打开 Mac 应用，或连接运行中的窗口。应用继续运行在 Mac 当前登录桌面，也会显示在 Mac 本机。Ubuntu 窗口关闭只断开连接；需要退出 Mac 应用时使用应用自身的退出入口。

若系统列表显示已开启，应用仍提示缺少权限，可点“显示共享组件”，核对访达选中的 `RemoteAppNode.app`。开发资源目录和打包应用内可能各有一份同名组件，应使用当前产品显示的那份。旧版本直接启动组件二进制，系统会把部分权限检查归给管理进程；升级后需将原先只授给管理进程的录屏权限补授给共享组件。请按应用显示的实际权限状态操作，无需修改系统权限数据库。

当前开发包使用临时签名，组件代码更新后，macOS 可能仍保留旧版本的授权记录。若列表显示开启而实际检测失败，应从相应权限列表移除旧组件，再添加“显示共享组件”选中的当前版本；只切换开关可能无法更新旧记录。这是开发签名的限制，发布前仍需稳定的正式签名与升级验证。

Mac 管理窗口的红色关闭按钮会隐藏管理界面，连接任务继续运行；点击 Dock 可再次打开。停止共享会结束本机发布的采集与控制，保留应用进程，也不结束正在接收的 Ubuntu 应用。QUIC 网络组件与设备身份独立管理，已打开的接收窗口继续绑定原设备。

## 连接和身份

QUIC 连接由两端同一 Rust 网络组件管理，支持双向发起、设备持久证书和独立路由。端口、配对撤销、地址变更和可靠流规则见[统一传输指南](native-transport.md)。产品不再注册 SSH 返回 socket。

Mac 和 Ubuntu 的目录缓存、窗口宿主及重连任务各自保留设备 UUID。切换设备列表不改变已有窗口的目标；撤销一台设备不会撤销其他配对。每个操作系统用户有独立网络状态和身份，不能复制其他设备私钥作为新设备。

身份和配对位于 `~/.local/state/lan-remoteapp/network/`，目录 0700、文件和本机路由 socket 0600。Linux 不再读取历史 `peers/` 返回路由记录。Mac 管理 socket 和发布 socket 分开，只有前者允许本机共享及权限操作。发布服务有单实例锁，健康检查断开不会结束服务。

## 采集、输入和剪贴板

Mac 使用 ScreenCaptureKit 的 `desktopIndependentWindow` 过滤，只采集选定窗口；VideoToolbox 输出 H.264，Ubuntu 使用 GStreamer 解码并显示在 GTK 原生窗口。原始帧在编码前合并，编码包保持顺序，尺寸变化和重连从新的关键帧开始。帧和解码像素受限，Ubuntu 在解码前检查 SPS 尺寸。该方向首版需要 H.264 运行组件，没有 PNG 回退。

Ubuntu 使用本机 GTK 输入上下文完成中文预编辑和候选，提交 Unicode 给 Mac。普通按键使用协商后的逻辑键接口，Ubuntu 的 Control 快捷键对应 Mac Command；原来的 Mac → Ubuntu 键码映射不变。指针按所选窗口坐标换算；窗口操作和输入都复核 PID、应用启动时间和所选窗口归属。锁屏、窗口退出和权限变化会停止对应控制与采集。

鼠标只向所选窗口的拥有进程投递，保留全局与窗口内两套命中坐标；点击和主动剪贴板操作等待目标应用激活，避免首个事件早于激活完成。窗口内坐标依赖运行时解析的 `CGEventSetWindowLocation` 私有接口；缺失时返回不支持输入，不回退到全桌面事件注入。该接口及应用兼容性仍需随 macOS 版本验证。

复制、剪切、粘贴通过自有协议主动执行，无后台剪贴板同步。Mac → Ubuntu 方向的双向文本限制为 8 KiB，PNG、文件和目录合计限制为 8 MiB / 256 项，文件为复制。接收前检查路径、父目录、重复名称和大小；不解压任意归档。复制结果关联请求、设备与窗口，旧请求不能覆盖更新的本机复制操作。原 Ubuntu → Mac 的独立大文件通道和既有上限保持原样。

接收窗口不会再次发布：Mac 按接收应用包身份和受管理 `WindowHosts` 路径排除；Ubuntu 按接收管理进程的 PID、`/proc` 启动时间登记排除运行窗口，并排除本产品桌面入口。过滤不依赖窗口标题。

## 当前验收边界

首版只发布选定的 Mac 主窗口，复杂子窗口、菜单和原生应用焦点争用仍需扩展；不创建独立后台 Mac 图形会话。当前系统权限、真实双机验收进度和回归结果见 [验证记录](validation.md)。隔离 GTK/GStreamer 通过，不代表 ScreenCaptureKit、真实输入法或所有 Mac 应用均已通过双机验收。
