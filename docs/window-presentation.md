# 通用子窗口展示修复（2026-10-25）

## 原因与行为

原生 Wayland 桥接之前没有传递窗口类型，Agent 把所有 transient 都标为 dialog，并把位置写成零。Mac 因而给菜单、提示框加了普通窗口标题栏、居中显示并尝试激活它们。这个问题与应用名称或是否另开进程无关。

新版传递源坐标矩形、合成器窗口类型、父窗口和堆叠次序。Mac 通过父窗口实际图像区域换算位置与大小，保留留边、分数密度和嵌套关系：

| 源类型 | Mac 展示与输入 |
| --- | --- |
| 主窗口、普通对话框 | 正常窗口；关联对话框按原相对位置显示 |
| 菜单、组合框、临时浮层 | 无标题栏附属窗口，允许超出父窗口边界；保持所属主窗口的键盘响应，鼠标仍使用子窗口本地像素坐标 |
| 提示框、拖放标记、通知 | 无标题栏浮层，不抢键盘焦点，不拦截鼠标 |

窗口类型来自 GNOME Meta.WindowType 或 X11 EWMH/override-redirect；授权范围继续依赖明确 transient 关系，不按应用、标题、尺寸或同 PID 扩大范围。X11 堆叠次序来自根窗口树，并穿过窗口管理器装饰层定位客户端。已经由源端合成的 subsurface 保留在原视频中。

独立合成器窗口仍可独立编码传输，由 macOS 窗口系统叠放，不增加主窗口像素合成与复制。H.264 视频仍不携带透明通道；这次修复不宣称任意透明/异形窗口都能无损还原。

## 生命周期与性能边界

PipeWire 节点就绪信号改由后续请求推进，pending 时不在同步输入路径中运行最长三秒的嵌套 GLib 循环。关闭、消失或初始化失败的短暂子窗口不会直接中止主窗口连接。真实 GNOME 测试还发现新 xdg_popup 在首次 configure 前可能报告零尺寸：新窗口等待有效几何；已经发布的窗口保留身份并暂时隐藏。

Mac 在父窗口无匹配画面、隐藏、最小化、销毁或关系成环时隐藏子窗口。细窄提示框不再受隐藏恢复按钮的固有宽度撑大；浮层使用不要求 key window 的鼠标跟踪。仅在子窗口堆叠顺序变化时重排本地窗口。

本次未重新测量真实 IDEA 的端到端延迟，不把移除等待或通过功能测试当作已取得整体延迟改善。此前测量仍见[端到端延迟报告](performance/2026-10-24-live-agent-latency.md)。
