# 实现架构与设计差异

## MVP 决策

保留原方案的 Rust 业务核心、Tauri 管理 UI、Linux 用户 Agent、Swift/AppKit WindowHost。Ubuntu 端默认创建产品自己的虚拟 X11 会话，也可按授权范围接入当前桌面的 X11/Xwayland 应用；不发布完整桌面。

当前采用公共 Rust 传输层和唯一的 QUIC 网络通道。控制、每窗口视频和低优先级文件使用独立可靠流，设备通过证书和一次性邀请配对；本机 RWP/1 保留 JSON/base64，网络视频为二进制。详见[统一传输指南](native-transport.md)。

## 窗口与图像

Agent 发现产品会话内的可见窗口，发送元数据及窗口视频。服务端显式配置 existing 时，也可按 PID 接入原桌面已有 X11 窗口，使用 XComposite pixmap 捕获。独立输出线程通过系统 GStreamer C API 将已验证窗口的只读原始像素缓冲直接交给 OpenH264，使用 Arc 生命周期租约避免跨进程传帧和重复拷贝；不重新采集整个桌面。Swift 宿主按窗口使用 VideoToolbox 解码，再由 NSView/CoreGraphics 显示，未使用 Metal。默认上限 60 fps，可选择 90 fps；已显示帧反馈过慢时自动降到最低 15 fps，实际帧率仍受编码、网络及控制端限制。

XDamage 将已授权可见窗口的重绘合并为待采集状态；私有请求唤醒 socket 和 X11 fd 一起等待就绪。元数据检查与采集时钟分离，空闲后第一次重绘可立即进入采集，静止窗口无需反复读取整窗。不支持扩展时回退轮询，尺寸变更和新控制端连接强制提供快照。剪贴板状态机和采集共用连接时，由事件分发保留其选择区/属性事件。

在编码之前合并待处理原始帧，避免画面排队；已编码的 P 帧按序发送、解码，只在解码后合并待显示图像。每个编码流从关键帧开始，resize、隐藏恢复、重连重建流。原始帧队列、去重缓存、解码总像素和包大小均受限。窗口副标题显示分辨率、UI 缩放及视频/PNG 模式。

窗口销毁后不能接受旧帧；大小变更带 geometry_revision。队列与解码尺寸必须有上限，无法正确解码的帧被拒绝而不是无限缓存。NSWindow 操作在主线程，网络读取不阻塞 UI。

远端宽高使用渲染像素，AppKit 宿主使用逻辑点数；自动模式以本机 backing 像素密度换算，与远端工具包界面缩放独立。默认持续根据本机窗口请求宽高，迟到的远端几何数据只更新画面，不改变本机窗口大小；自动模式铺满窗口，手动模式固定远端分辨率、按比例显示并映射鼠标。新独立会话在进程启动前设置工具包缩放，已有原桌面应用不修改全局 DPI。WM 辅助窗口不发布，最大化窗口经 EWMH 请求调整，避免重复聚焦隐藏窗口及超限窗口被静默丢弃。

## 生命周期

远端用户服务拥有应用会话；网络桥接只拥有连接。Mac 窗口红色关闭按钮和退出宿主均只断开连接；关闭远端程序由应用画面内的关闭按钮或退出菜单完成，连接掉线不能当作应用退出。会话重附着用 snapshot 重建状态；同一会话只允许一个控制端。Agent 服务自身被停止、机器重启或 X server 崩溃不保证工作保留，必须如实诊断。

existing 会话只持有 X11 连接和进程身份，不拥有原进程。Agent 停止不结束它；下次连接重新校验 UID、可执行文件与启动时间，避免 PID 重用后误接其他进程。窗口元数据及输入均检查归属，原桌面的其他窗口不进入此会话。

## 原生链路

服务端通过 GIO 发现已安装桌面应用和真实 PNG 图标，自定义 apps.json 保留固定入口。运行窗口通过只读 X11 / XRes 元数据另行发现，并按用户、进程启动时间及选中窗口限定接管范围。应用、运行窗口和远程会话分开显示；没有客户端可执行路径或任意命令接口。见 [应用与窗口发现](application-discovery.md)。

QUIC 控制、按窗口视频和原生接收宿主组成当前路径。启动器先幂等创建会话，再附着原生宿主；会话列表用于恢复。产品没有 SSH 登录、密码配置或返回通道；设备身份、缓存与恢复按 UUID 隔离。

## 统一节点架构

2026-10-22 确定的产品方向：每个平台安装一个 窗渡 PaneFerry，每台设备同时具备发布本机应用和接收远端应用的能力。Mac 发布和 Ubuntu 接收组件已加入，具体交付与验证状态见 [Mac 发布指南](mac-publishing.md)；Ubuntu → Mac 保留原有链路，反向真实双机和多设备并发的验收边界单独记录。下文同时包含已建立的扩展点和后续目标。

### 产品与服务边界

同一个管理界面提供“本机应用共享”“远端设备与应用”和“当前会话”。本机服务统一维护配置与连接，并管理平台辅助组件。发布、接收可独立启停，也可同时工作；不设置客户端版/服务端版，也不要求用户分别安装 Agent 和 WindowHost。

一个产品安装包可以包含后台服务和窗口辅助进程。平台需要的进程隔离、系统权限和窗口生命周期由产品管理，不以强制单进程作为统一服务的标准。macOS 与 Ubuntu 分别构建适合本平台的安装包，共享业务核心和协议。

| 层次 | 共同职责 | 平台差异 |
|:--|:--|:--|
| 管理界面 | 本机共享设置、远端目录、入站/出站会话、状态诊断 | 系统权限入口与桌面集成 |
| 本机服务核心 | 配置、连接、认证协调、会话生命周期、能力协商 | macOS 用户图形会话服务与 Linux 用户服务的启动方式 |
| 发布后端 | 应用发现/启动、窗口元数据、采集编码、输入与剪贴板执行 | Linux X11；新增 macOS 窗口后端 |
| 接收窗口宿主 | 本机独立窗口、解码显示、输入法、输入与剪贴板请求 | 现有 AppKit；新增 Ubuntu 窗口宿主 |
| 传输与协议 | 窗口、画面、输入、重连与错误语义 | 共享 RWP 和配对 QUIC，平台能力显式协商 |

应用进程和发布会话始终由应用所在设备管理，接收端只附着和操作。发布与接收不是整机角色：Mac 发布应用给 Ubuntu 的同时，可以接收 Ubuntu 的应用。会话和窗口必须按远端设备、会话及窗口身份区分，避免不同设备的同名应用或相同窗口编号冲突。

现有单控制端规则继续按发布会话执行。停止本机共享只处理入站控制与采集，不能结束本机正在接收的远端应用，也不能默认杀死已发布的应用；退出管理界面、停止共享和退出后台服务需要各自明确的生命周期。

### 多设备扩展约束

统一服务从数据模型和接口开始支持多个远端上下文，设备数量不写死为一台或两台。例如 Mac A 可同时连接 Ubuntu B、Ubuntu C；与此同时，Ubuntu B 也可连接 Mac A 发布的应用。首版可以逐步补齐多设备界面，这些扩展点必须随服务拆分保留，完整并发能力仍需后续实现和验收。

设备身份、连接配置与实际网络连接分开管理。设备有持久的 `device_id`，IP/主机名和端口属于可变连接地址；地址相同不能直接认定为同一设备，远端自行报告的 ID 也不能代替配对证书验证。旧 SSH 配置被停用，不能据此自动配对或继承信任；已有 QUIC 设备身份和缓存保留。

以下为目标模型中的作用域，不表示现有 RWP/1 已新增这些字段：

| 对象 | 隔离与归属 |
|:--|:--|
| 远端上下文 | 按 `device_id` 标识；每个操作系统用户运行独立节点，拥有各自身份、目录、授权和会话 |
| 连接管理 | 持有多个远端上下文，每个上下文管理自己的控制/媒体连接、状态、超时和重连任务 |
| 应用与目录 | 以远端上下文 + `app_id` 为键；同名应用可同时存在，界面和窗口标明来源设备 |
| 会话与窗口 | 会话以远端上下文 + `session_id` 为键；窗口再加 `window_id`，不把远端局部编号作为全局标识 |
| 请求与回包 | 关联远端上下文、会话、请求 ID 和连接代次；重连或移除设备后，旧连接的迟到结果不能更新新状态 |

服务操作必须显式携带远端上下文或带归属的会话/窗口句柄，不依赖全局 `currentEndpoint`。界面中的“当前设备”只是浏览选择；已有窗口持续绑定原设备，切换列表不能改写其键鼠、剪贴板、关闭和重连的目标。连接单台、断开单台、停止本机共享及断开全部是不同操作，移除或重连一台设备不清理其他设备的状态。

剪贴板请求按目标设备和窗口关联；本机系统剪贴板仍是共享资源，由统一服务仲裁主动复制操作，只接受仍有效的用户请求结果，较早复制的迟到回包不能覆盖较新的复制结果。粘贴在触发时固定目标，不随随后切换设备而改发；不增加设备间后台剪贴板同步。

资源预算同时设置单设备/单会话限制与本机总量限制，覆盖连接数、解码像素、缓存、传输队列和重试频率。多个设备独立重连与背压，单台设备断线或接收缓慢不应阻塞其他设备；扩展多设备不能绕过现有总资源限制。

一台设备允许来自多台设备的连接，单控制端规则仍作用于具体发布会话。同一会话的多人同时控制不在本次扩展范围；Mac 当前桌面下不同应用会话仍可能争用本机焦点，多设备连接不代表获得彼此隔离的图形桌面。

### 平台能力与 Mac 发布边界

| 平台 | 发布本机应用 | 接收远端应用 |
|:--|:--|:--|
| Ubuntu | 已有 X11/XWayland 后端及独立 Xvfb 会话 | 已加入 GTK 窗口、H.264 解码、本机输入法和重连；真实 Mac 窗口接收及基础交互通过 |
| macOS | 已加入应用发现、SCK 窗口采集、输入与会话组件；真实画面、点击、Unicode 提交、文本剪贴板与重连通过 | 已有 Swift/AppKit WindowHost |

Mac 发布首版使用当前已登录图形桌面：应用仍在 Mac 本机运行和显示，Ubuntu 远程访问其选定窗口。用户已于 2026-10-22 确认允许窗口同时显示在 Mac 本机，优先打通 Mac 本机应用的远程使用；独立后台图形会话不属于首版范围。此决定不改变排除收到的远程应用的规则。Mac 本地操作与远端操作可能争用应用焦点，需要在真实应用上验收。

macOS 采集使用 ScreenCaptureKit 的指定窗口过滤，输入控制另行检查系统授权；录屏授权不能代表输入控制授权。涉及图形和权限的组件应运行在正确的用户图形会话中，QUIC 网络组件只连接该服务，不能用临时无图形进程替代这一生命周期。

能力描述需要区分平台支持、组件安装、用户开启共享、系统授权和当前可用状态。权限撤销、桌面退出或窗口消失时，停止对应采集与输入，并给出可恢复的状态；不能将“服务在线”解释为“可以远程控制”。

本机共享目录只发布在本机实际运行的应用。从其他设备接收的远程应用、其接收窗口和生成的本机应用入口均不进入共享目录。例如 Ubuntu A → Mac 的应用不会出现在 Ubuntu B 读取的 Mac 应用/窗口列表中。排除需覆盖已安装应用发现与运行窗口发现，并依据产品登记的接收宿主身份、进程与窗口归属执行，不能仅按标题过滤；Mac 的 `WindowHosts` 缓存应用包也不能被重新当作本机应用发布。

依据：[ScreenCaptureKit 指定窗口过滤](https://developer.apple.com/documentation/screencapturekit/sccontentfilter/init(desktopindependentwindow:))、[屏幕采集与录屏授权](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos)、[辅助功能授权状态](https://developer.apple.com/documentation/applicationservices/1459186-axisprocesstrustedwithoptions)。

### 从现有实现迁移

1. 抽离统一本机服务核心。当前 `apps/linux-agent/src/main.rs` 直接持有 X11 `Backend`、Xvfb 子进程及 `/proc` 身份校验，需要保留在 Linux 发布实现中；连接、控制权和会话管理提取为共享逻辑，连接管理器持有多个独立远端上下文，所有操作显式指定目标。通过配对 QUIC 的私有路由连接发布器。
2. 移除公共接口中的平台假设。现有会话 `display` 是 X11 显示号，按键 `keysym` 是 X11 语义，快捷键使用 Mac → Linux 映射。扩展时将平台专属信息留给对应实现，协商跨平台输入和能力；旧协议请求禁止未知字段，不能直接给旧端发送新增字段。新旧端需要明确兼容或报出版本不支持。
3. 让启动器按本机平台选择接收宿主，补齐 Ubuntu 的窗口显示、H.264/PNG 解码、键鼠、文本提交和重连。当前 `native_host` 仅允许 macOS，应用身份缓存也包含 Mac 专属实现，需要分别适配。
4. 增加 Mac 发布后端，按本机批准的应用/窗口目录执行启动和附着；复用会话、窗口、画面和断线恢复语义。先验证一个真实应用的画面与交互，再扩展多窗口、剪贴板和更多应用。
5. 将本机服务、发布组件和接收宿主纳入各平台同一安装、启动、升级与卸载流程；随后验收双向并发。用户无需手工拼装两个角色的程序。

两个方向复用已配对节点的 QUIC 设备连接，通过独立可靠流传输。底层连接可以保持请求方与响应方，设备身份不随连接方向改变。

### 下一阶段验收

- 每个平台使用一个产品安装包，管理入口同时显示本机发布与远端应用；平台辅助组件由产品管理。
- Ubuntu → Mac 的现有应用启动、输入、剪贴板和重连行为继续通过原有验证。
- Ubuntu 能列出获准发布的 Mac 应用/窗口，在本机独立窗口中显示并操作；中文提交、快捷键、尺寸变化和权限错误有实际验证记录。
- 首版在 Mac 用户已登录的图形桌面验证，允许同一个应用窗口同时显示在 Mac 本机和 Ubuntu；不以本机隐藏窗口或独立后台图形会话作为通过条件。
- Mac → Ubuntu 与 Ubuntu → Mac 同时运行，目录、控制权、窗口身份和剪贴板请求不会串到另一方向；关闭一个方向不影响另一个方向。
- 服务接口和状态模型能表达多个远端上下文；覆盖两台设备使用相同应用、会话和窗口编号的场景，确保选择设备、输入、复制粘贴、重连及迟到回包不串设备。实际多设备功能交付时，以同时连接至少两台远端、断开其中一台而另一台继续可用作为验收条件。
- 从 Ubuntu A 接收的应用及其本机入口，不出现在 Mac 的本机共享列表，也不出现在 Ubuntu B 读取的 Mac 应用/窗口目录；反方向执行相同排除规则。
- 接收端关闭或短暂断线保留发布端应用；恢复时重新校验窗口身份并附着同一会话。应用退出、权限撤销与后台服务退出分别有明确结果。
- Mac 已登录桌面模式、最小化、锁屏、注销和本地/远端焦点竞争单独记录；编译或协议测试通过不能替代双机验收。
